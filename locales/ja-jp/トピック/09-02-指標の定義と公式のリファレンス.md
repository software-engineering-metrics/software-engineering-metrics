# 9.2 指標の定義と公式のリファレンス

本書のすべての公式を一箇所に集めたもの。各項目は、そのゲーミングのリスクとガードレールを含む完全な議論がある章を示します。これをクイックルックアップとして使い、章自体の代わりとしては使わないでください。

## フローの指標(第2部)

| 指標 | 公式 | 章 |
| --- | --- | --- |
| フロー速度 | 単位時間あたりに完了したフローアイテムの件数 | 2.3 |
| フロー分布 | (ある種類のフローアイテムの完了した件数) / (完了した総件数) x 100% | 2.3 |
| フロータイム | フローアイテムがバリューストリームに入ってからその提供までの時間 | 2.4 |
| フロー負荷 | バリューストリーム内で現在アクティブあるいは待機しているフローアイテムの件数 | 2.4 |
| リトルの法則 | フロー負荷(仕掛かり作業)= 到着率 x フロータイム(サイクルタイム) | 2.4、2.7 |
| フロー効率 | アクティブな作業時間 / 総経過時間 x 100% | 2.5 |
| サイクルタイム | 段階の期間の合計:コーディング + 受け渡し + レビュー + テスト + デプロイ | 2.6 |
| 稼働率 | 到着率 / サービス率 | 2.7 |
| 完了正確率(%C/A) | (手直しなしに下流で使用可能な単位) / (総単位) x 100% | 2.8 |
| 総合通過収率 | 段階1の%C/A x 段階2の%C/A x ... x 段階Nの%C/A | 2.8 |
| タクトタイム | 利用可能な作業時間 / その期間の顧客の需要 | 2.8 |
| 最初のレビューまでの時間 | プルリクエストが開かれてから最初の実質的なレビュアーの応答までの時間 | 2.9 |
| デプロイ頻度 | 単位時間あたりの成功した本番環境へのデプロイの件数 | 2.10 |
| 変更のリードタイム | 最初のコミットから成功した本番環境へのデプロイまでの時間(中央値と90パーセンタイルを報告) | 2.10 |
| 変更失敗率 | (失敗を引き起こすデプロイ) / (総デプロイ) x 100% | 2.10 |
| 失敗したデプロイの復旧時間 | 失敗の検知から本物のサービスの復旧までの時間 | 2.10 |

## 開発者体験(第3部)

| 指標 | 公式 | 章 |
| --- | --- | --- |
| 集中時間 | カレンダーのデータから、週あたりの2時間以上の中断されないブロックの件数と期間 | 3.6 |
| 回答率 | (受け取った調査の回答) / (送られた調査の招待) x 100% | 3.7 |

## コードと品質(第4部)

| 指標 | 公式 | 章 |
| --- | --- | --- |
| サイクロマティック複雑度 | 制御フローを通る独立したパス(エッジ − ノード + 2、McCabeによる) | 4.1 |
| テストカバレッジ | (テストによって実行された行/分岐) / (総行数/分岐数) x 100% | 4.2 |
| ミューテーションキル率 | (テストスイートによって殺されたミュータント) / (導入された総ミュータント) x 100% | 4.2 |
| コードチャーン | 時間枠にわたってファイルごとに追加 + 変更 + 削除された行数 | 4.3 |
| ホットスポットスコア | チャーン x 複雑さ、ファイルごとにランク付け | 4.3 |
| 負債の抱え続けるコスト | 項目を修正しないことの継続的なコストの見積もり(関連する仕事の遅延、高まった欠陥のリスク) | 4.5 |

## 製品とビジネス(第5部)

| 指標 | 公式 | 章 |
| --- | --- | --- |
| エスケープした欠陥率 | (重大度加重のエスケープした欠陥) / (提供の単位あるいは時間) | 5.1 |
| 初期採用 | (機能を少なくとも一度試したユーザー) / (対象観客) x 100% | 5.2 |
| 定着した採用 | (N週間後にまだ機能を使っているユーザー) / (最初にそれを試したユーザー) x 100% | 5.2 |
| 単位コスト | 総コスト(人員 + インフラ + ツール) / 意味のある単位(顧客、取引) | 5.4 |
| ROI | (総利益 − 総所有コスト) / 総所有コスト、範囲として提示 | 5.5 |

## 信頼性、運用、セキュリティ(第6部)

| 指標 | 公式 | 章 |
| --- | --- | --- |
| エラーバジェット | (1 − SLO目標) x 期間(例:30日間の0.1%≈43分) | 6.1 |
| エラーバジェットの消費率 | 消費されたエラーバジェット / 割り当てられたエラーバジェット、与えられた期間にわたって | 6.1 |
| MTTD | インシデントの発生から検知までの時間 | 6.2 |
| MTTA | インシデントの通知から確認までの時間 | 6.2 |
| MTTR(インシデント) | 確認から本物のサービスの復旧までの時間 | 6.2 |
| オンコールのページ分配 | ローリングウィンドウにわたって個人ごとに受け取ったページ(チームの平均ではない) | 6.3 |
| 脆弱性の是正までの時間 | 発見から本物の是正までの時間、重大度別に追跡 | 6.4 |

## これらの公式を使うことについての注意事項

- **速度あるいはアウトプットの公式を常にそのガードレールと組み合わせてください**(第1.2章):変更失敗率をデプロイ頻度とリードタイムと、エスケープした欠陥率を提供の速度と、エラーバジェットの消費をデプロイの活動とです。
- 公式が明示的に平均を求めていない限り、**時間に基づく公式には平均ではなく中央値とパーセンタイルを使ってください**(第1.6章)。
- **すべての公式は、その数学的な定義とともに文書化された情報源のシステムと収集方法を必要とします**(第1.5章)。異なる情報源から同じ公式を計算する二つのチームは、比較可能な数字を生み出しません。
- **重大度加重は上記のすべての公式で明示的には示されていません**が、「重大度加重」が現れるところではどこでも適用されます。完全な分類の仕組みについては該当する章を参照してください。
