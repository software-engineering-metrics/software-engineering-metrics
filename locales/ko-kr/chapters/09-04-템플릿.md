# 9.4 템플릿

반복되는 문서를 위한 복사-붙여넣기 템플릿. 처음 두 개의 실제로 작성된 예시는 `docs/examples/`에 있다.

## 메트릭 헌장 템플릿

```markdown
# 메트릭 헌장: [팀 또는 메트릭 집합 이름]

- **팀:** [소유 팀]
- **소유자:** [명명된 사람 또는 역할]
- **검토됨:** [주기, 예: 분기별]

## 목적

[한두 문장: 이 헌장이 무엇을 거버넌스하고 왜 그런지.]

## 우리가 추적하는 것

| 메트릭 | 진실의 소스 | 소유자 |
| --- | --- | --- |
| [메트릭] | [시스템] | [명명된 소유자] |

## 비목표

[이 메트릭이 사용되지 않는 것에 대한 명시적인 진술, 예: 개인 성과 평가,
맥락 없는 팀 간 순위 매기기.]

## 가드레일

[각 인센티브화된 메트릭에 대해, 그 짝지어진 가드레일과 그것이 포착하는
게임화 패턴을 명명하라.]

## 검토 주기

[이 헌장이 언제 어떻게 재검토되는지; 메트릭 퇴역을 촉발하는 것.]
```

## 대시보드 사양 템플릿

```markdown
# 대시보드 사양: [대시보드 이름]

## 청중

[이 대시보드가 누구를 위한 것이며, 그것이 어떤 결정을 알리는지. 개인
평가를 위한 것이 아니라면 명시적으로 밝혀라.]

## 타일(표시 순서대로)

1. **[메트릭 이름]**, [시간 창], [차트 유형]. [특정 시각화 참고 사항:
   축 규칙, 주석.]
2. ...

## 시각화 규칙

- 타일에 예외가 문서화되지 않는 한 축은 0에서 시작한다.
- [다른 프로젝트 특화 정직함 규칙.]

## 새로고침 주기

[각 타일이 얼마나 자주 업데이트되며, 어떤 소스로부터인지.]

## 이 대시보드가 의도적으로 제외하는 것

[의도적으로 제외된 것이 있다면 그것을 명명하고 왜 그런지, 예: 개인
활동 수.]
```

## 메트릭 검토 회의 안건 템플릿

```markdown
# 메트릭 검토: [날짜]

## 참석자

[이름과 역할]

## 검토된 메트릭

각 메트릭에 대해:
- 현재 수치와 추세
- 정상적인 변동을 벗어난 움직임(1.6장)
- 짝지어진 가드레일 상태, 해당하는 경우
- 이 수치가 알리는 결정, 있다면

## 제안된 새로운 메트릭

[각각을 새 메트릭 검토 체크리스트(9.3장)를 통해 실행하라.]

## 퇴역이 고려되는 메트릭

[지난 두 주기 동안 어떤 메트릭이 결정을 알리지 못했는가?]

## 조치 항목

| 항목 | 소유자 | 기한 |
| --- | --- | --- |
| | | |
```

## 비난 없는 포스트모템 템플릿

```markdown
# 포스트모템: [인시던트 이름], [날짜]

## 요약

[한 단락: 무슨 일이 일어났는지, 사용자 영향, 기간.]

## 타임라인

- 감지: [시간, 어떻게 감지되었는지]
- 인지: [시간, 누가 대응했는지]
- 해결: [시간, 무엇이 그것을 고쳤는지]

## 심각도

[문서화된 기준에 맞선 분류, 6.2장.]

## 근본 원인

[무엇이 이것이 일어나도록 허용했는지, 개인적인 질문이 아니라 시스템
질문으로 프레이밍됨.]

## 잘된 것

[대응에서 작동한 구체적인 것들.]

## 조치 항목

| 항목 | 소유자 | 기한 |
| --- | --- | --- |
| | | |

## 후속 조치

[조치 항목이 다음 검토 주기에 따라 완료까지 추적되었다는 확인.]
```

## ROI 사례 템플릿

```markdown
# ROI 사례: [이니셔티브 이름]

## 비용(총 소유 비용, 5.5장)

- 선행: [개발 비용]
- 지속적: [유지보수, 인프라, 지원, 연간]
- 기회 비용: [이 역량이 그 대신 할 수 있었던 것]

## 혜택(문서화된 증거, 5.1장-5.3장)

- [혜택 1], [데이터 소스]로 입증됨
- [혜택 2], [데이터 소스]로 입증됨

## 범위와 가정

- 보수적인 경우: [수치]
- 낙관적인 경우: [수치]
- 범위를 이끄는 핵심 가정: [그것을 명명하라]

## 고려되고 배제된 교란 요인

[투영된 혜택을 달리 설명할 수 있는 것은 무엇이며, 그것이 왜 배제되었거나
설명되었는지.]

## 완료 후 확인(이니셔티브 완료 후 작성)

- 실제 결과: [수치]
- 투영된 범위와 비교: [위 / 내 / 아래]
- 다음 추정치를 위해 이것이 우리에게 가르쳐 주는 것: [메모]
```
