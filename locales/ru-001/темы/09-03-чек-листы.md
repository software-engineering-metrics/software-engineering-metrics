# 9.3 Чек-листы

Готовые к использованию краткие справочные чек-листы. Скопируйте один в ваш собственный процесс и адаптируйте его; смысл в охвате, а не точной формулировке.

## Чек-лист пересмотра новой метрики (перед добавлением любой метрики на панель)

- [ ] У метрики есть именованное решение, которое она информирует (глава 1.1)
- [ ] Метрика классифицирована как диагностическая или оценочная, письменно (глава 1.1)
- [ ] Если стимулируемая, страховочная метрика определена одновременно (глава 1.2)
- [ ] Вектор манипулирования назван: как разумная команда заставила бы это число выглядеть хорошо, не улучшая реальный результат (глава 1.2)
- [ ] Метрика классифицирована как вход, выход или результат (глава 1.3)
- [ ] У метрики есть именованный владелец и задокументированная исходная система и метод сбора (главы 1.4, 1.5)
- [ ] Метрика будет использовать медиану или перцентиль, а не среднее, если лежащие в основе данные скошены (глава 1.6)
- [ ] Метрика никогда не используется для индивидуальной оценки, или это использование отдельно и явно раскрыто (глава 1.1)

## Чек-лист запуска панели

- [ ] У панели есть единая именованная, конкретная аудитория и решение (глава 8.1)
- [ ] Каждая стимулируемая метрика появляется на том же представлении, что её страховочная метрика (главы 1.2, 8.1)
- [ ] Оси начинаются с нуля, если заявленное, видимое исключение не задокументировано (глава 1.6)
- [ ] Показан тренд со временем, а не единый снимок (глава 1.6)
- [ ] У панели есть именованный владелец и каденция пересмотра (глава 1.4)
- [ ] Видимое заявление декларирует, для чего панель не предназначена, если релевантно (глава 1.1)
- [ ] У источников данных есть базовые проверки здоровья, так чтобы сломанный конвейер тихо не отображался как текущий (глава 1.5)

## Чек-лист развёртывания программы метрик

- [ ] Цель и явные не-цели сообщены перед запуском, а не реактивно (глава 8.3)
- [ ] Люди, которых измеряют, были вовлечены в выбор метрик (глава 8.3)
- [ ] Программа начинается в только диагностическом режиме, с обязательным минимальным доказательным периодом (глава 8.3)
- [ ] Существует быстрый, видимый протокол ответа для любого будущего инцидента неправильного использования (глава 8.3)
- [ ] Выбрана пилотная команда, подлинно вызвавшаяся добровольно, а не предписанная (глава 8.5)
- [ ] Основополагающее управление (устав, владение, диагностическая политика) на месте до начала инструментации (главы 1.4, 8.5)

## Чек-лист инцидента и разбора инцидента

- [ ] Разбор инцидента исследует систему, а не отдельного человека (глава 6.2)
- [ ] Серьёзность классифицирована против задокументированных, стандартизированных критериев (глава 6.2)
- [ ] Времена обнаружения, подтверждения и решения записаны отдельно (глава 6.2)
- [ ] Пункты действий конкретны, назначены и отслеживаются до завершения (глава 6.2)
- [ ] Разбор инцидента делится без страха индивидуальных последствий (главы 6.2, 8.3)

## Чек-лист аудита метрик эры ИИ

- [ ] Каждая метрика панели была проверена против: «показала бы команда, активно использующая помощь ИИ, но не производящая больше реальной ценности, улучшенное показание здесь» (глава 7.1)
- [ ] Доля неудачных изменений и частота дефектов пересматриваются наряду с любым ростом частоты развёртывания с помощью ИИ или объёма коммитов (глава 7.1)
- [ ] Мощность и глубина обзора отслеживаются по мере изменения объёма сгенерированного ИИ кода (глава 7.1)
- [ ] Утёкшие дефекты помечены по уровню помощи ИИ, чтобы проверить, а не предположить, держится ли ещё историческая связь частоты дефектов (главы 7.1, 7.3)
- [ ] Методы обнаружения, устойчивые к дефектам «выглядит правильно» (мутационное тестирование, тестирование на основе свойств), на месте для путей кода, насыщенных ИИ (глава 7.3)
- [ ] Устав метрик был явно пересмотрен и обновлён для этого сдвига, а не оставлен дрейфовать непроверенным (главы 1.4, 7.1)

## Чек-лист аудита программы метрик (ежегодный)

- [ ] У каждой метрики всё ещё есть именованный владелец (глава 1.4)
- [ ] По крайней мере одна метрика была выведена из эксплуатации в последнем цикле, если она перестала оправдывать себя (глава 1.1)
- [ ] Оценка зрелости по пяти измерениям была проведена честно, оценена по минимуму, а не среднему (глава 8.4)
- [ ] Ни одна метрика не дрейфовала от диагностического к оценочному использованию без явного, раскрытого решения (глава 1.1)
- [ ] Определения были точечно проверены против фактической инструментации на дрейф (главы 1.2, 2.4, 5.1, 6.2, 6.4)
- [ ] Соотношение результата к выработке на основных панелях было вычислено и пересмотрено (глава 7.4)
