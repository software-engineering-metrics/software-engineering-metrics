# 9.3 Контрольні списки

Готові до використання швидкі контрольні списки. Скопіюйте один у власний
процес і адаптуйте; важливе тут охоплення, а не точне формулювання.

## Контрольний список перегляду нової метрики (перш ніж додавати будь-яку метрику на дашборд)

- [ ] Метрика має назване рішення, яке вона інформує (тема 1.1)
- [ ] Метрику письмово класифіковано як діагностичну або оцінювальну
      (тема 1.1)
- [ ] Якщо вона зі стимулом, запобіжник визначено одночасно (тема 1.2)
- [ ] Вектор маніпулювання названо: як раціональна команда зробила б це число
      гарним, не покращуючи справжній результат (тема 1.2)
- [ ] Метрику класифіковано як вхід, випуск чи результат (тема 1.3)
- [ ] Метрика має іменованого власника, задокументовану систему-джерело й
      спосіб збору (теми 1.4, 1.5)
- [ ] Метрика використовуватиме медіану чи перцентиль, а не середнє, якщо
      базові дані асиметричні (тема 1.6)
- [ ] Метрику ніколи не використовують для оцінювання окремих людей, або таке
      використання окремо й явно оприлюднено (тема 1.1)

## Контрольний список запуску дашборда

- [ ] Дашборд має одну названу конкретну аудиторію й рішення
      (тема 8.1)
- [ ] Кожна метрика зі стимулом з'являється на тому самому представленні, що й її
      запобіжник (теми 1.2, 8.1)
- [ ] Осі починаються з нуля, якщо немає видимого задокументованого винятку
      (тема 1.6)
- [ ] Показано тренд у часі, а не один знімок (тема 1.6)
- [ ] Дашборд має іменованого власника й ритм перегляду (тема 1.4)
- [ ] Видиме твердження вказує, для чого дашборд не призначений, якщо це
      доречно (тема 1.1)
- [ ] Джерела даних мають базові перевірки стану, щоб зламаний конвеєр не
      тихо відображався як актуальний (тема 1.5)

## Контрольний список запровадження програми метрик

- [ ] Мету й явні не-цілі повідомлено до запуску, а не реактивно (тема 8.3)
- [ ] Людей, яких вимірюють, залучено до вибору метрик
      (тема 8.3)
- [ ] Програма починається в суто діагностичному режимі із зобов'язаним
      мінімальним періодом випробування (тема 8.3)
- [ ] Існує швидкий видимий протокол реагування на будь-який майбутній
      випадок хибного використання (тема 8.3)
- [ ] Пілотну команду обрано з тих, що справді зголосилися, а не призначену
      примусово (тема 8.5)
- [ ] Фундаментальне управління (хартія, відповідальність, діагностична
      політика) є до початку інструментування (теми 1.4, 8.5)

## Контрольний список інциденту й постмортему

- [ ] Постмортем досліджує систему, а не окрему людину
      (тема 6.2)
- [ ] Серйозність класифіковано за задокументованими стандартизованими
      критеріями (тема 6.2)
- [ ] Час виявлення, підтвердження й усунення записано окремо
      (тема 6.2)
- [ ] Пункти дій конкретні, призначені й відстежуються до завершення
      (тема 6.2)
- [ ] Постмортем поширюють без страху індивідуальних наслідків
      (теми 6.2, 8.3)

## Контрольний список аудиту метрик для епохи ШІ

- [ ] Кожну метрику дашборда перевірено за запитанням: «чи показала б команда,
      що активно користується допомогою ШІ, але не створює більше справжньої
      цінності, тут покращення» (тема 7.1)
- [ ] Частку невдалих змін і рівень дефектів переглядають поряд із будь-яким
      зростанням частоти розгортань чи обсягу комітів за підтримки ШІ
      (тема 7.1)
- [ ] Потужність і глибину рев'ю відстежують, коли змінюється обсяг коду,
      згенерованого ШІ (тема 7.1)
- [ ] Дефекти, що прослизнули, позначено за рівнем допомоги ШІ, щоб перевіряти,
      а не припускати, чи історичний зв'язок рівня дефектів досі чинний
      (теми 7.1, 7.3)
- [ ] Методи виявлення, стійкі до дефектів, що «виглядають правильними»
      (мутаційне тестування, тестування на основі властивостей), є для шляхів
      коду з великою часткою ШІ (тема 7.3)
- [ ] Хартію метрик явно переглянуто й оновлено під цей зсув, а не залишено
      дрейфувати без уваги (теми 1.4, 7.1)

## Контрольний список аудиту програми метрик (щорічний)

- [ ] Кожна метрика досі має іменованого власника (тема 1.4)
- [ ] Принаймні одну метрику виведено з ужитку в останньому циклі, якщо вона
      перестала виправдовувати себе (тема 1.1)
- [ ] П'ятивимірне оцінювання зрілості проведено чесно, оцінено за мінімумом, а
      не середнім (тема 8.4)
- [ ] Жодна метрика не дрейфувала від діагностичного до оцінювального
      використання без явного оприлюдненого рішення (тема 1.1)
- [ ] Визначення вибірково звірено з фактичним інструментуванням на дрейф
      (теми 1.2, 2.4, 5.1, 6.2, 6.4)
- [ ] Співвідношення результатів і випуску на основних дашбордах підраховано й
      переглянуто (тема 7.4)
