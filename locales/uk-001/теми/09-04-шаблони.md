# 9.4 Шаблони

Шаблони для копіювання й вставлення для документів, що повторюються.
Опрацьовані, заповнені приклади перших двох лежать у розділі [«Приклади»](../приклади/огляд.md).

## Шаблон хартії метрик

```markdown
# Хартія метрик: [назва команди чи набору метрик]

- **Команда:** [відповідальна команда]
- **Власник:** [названа особа чи роль]
- **Перегляд:** [ритм, наприклад щокварталу]

## Мета

[Одне-два речення: що регулює ця хартія і навіщо.]

## Що ми відстежуємо

| Метрика | Першоджерело істини | Власник |
| --- | --- | --- |
| [метрика] | [система] | [названий власник] |

## Не-цілі

[Явне твердження, для чого ці метрики не використовують, наприклад
індивідуальне оцінювання результативності, ранжування команд без контексту.]

## Запобіжники

[Для кожної метрики зі стимулом назвіть її парний запобіжник і який шаблон
маніпулювання він ловить.]

## Ритм перегляду

[Коли й як цю хартію переглядають; що запускає виведення метрики з ужитку.]
```

## Шаблон специфікації дашборда

```markdown
# Специфікація дашборда: [назва дашборда]

## Аудиторія

[Для кого цей дашборд і яке рішення він інформує. Явно вкажіть, якщо він не
для оцінювання окремих людей.]

## Плитки (у порядку відображення)

1. **[Назва метрики]**, [часове вікно], [тип діаграми]. [Будь-які конкретні
   примітки до візуалізації: правила осей, анотації.]
2. ...

## Правила візуалізації

- Осі починаються з нуля, якщо не зазначено інше, а виняток
  задокументовано на плитці.
- [Будь-які інші специфічні для проєкту правила чесності.]

## Ритм оновлення

[Як часто оновлюється кожна плитка і з якого джерела.]

## Що цей дашборд свідомо виключає

[Назвіть усе, що навмисно залишено поза ним, і чому, наприклад кількість
активності окремих людей.]
```

## Шаблон порядку денного наради з перегляду метрик

```markdown
# Перегляд метрик: [дата]

## Учасники

[Імена та ролі]

## Переглянуті метрики

Для кожної метрики:
- Поточне значення й тренд
- Будь-який рух за межами нормальної варіації (тема 1.6)
- Стан парного запобіжника, якщо застосовно
- Рішення, яке це значення інформує, якщо є

## Запропоновані нові метрики

[Пропустіть кожну через контрольний список перегляду нової метрики, тема 9.3.]

## Метрики, розглянуті для виведення з ужитку

[Які метрики не інформували жодного рішення за останні два цикли?]

## Пункти дій

| Пункт | Власник | Термін |
| --- | --- | --- |
| | | |
```

## Шаблон постмортему без звинувачень

```markdown
# Постмортем: [назва інциденту], [дата]

## Підсумок

[Один абзац: що сталося, вплив на користувачів, тривалість.]

## Хронологія

- Виявлення: [час, як виявлено]
- Підтвердження: [час, хто відреагував]
- Усунення: [час, що виправило]

## Серйозність

[Класифікація за задокументованими критеріями, тема 6.2.]

## Першопричина

[Що дозволило цьому статися, сформульоване як питання про систему, а не про
окрему людину.]

## Що пройшло добре

[Конкретні речі, що спрацювали в реагуванні.]

## Пункти дій

| Пункт | Власник | Термін |
| --- | --- | --- |
| | | |

## Подальші кроки

[Підтвердження, що пункти дій відстежено до завершення, за наступним циклом
перегляду.]
```

## Шаблон обґрунтування ROI

```markdown
# Обґрунтування ROI: [назва ініціативи]

## Вартість (сукупна вартість володіння, тема 5.5)

- Початкова: [вартість розробки]
- Поточна: [супровід, інфраструктура, підтримка, на рік]
- Вартість упущеної можливості: [що ще могла б зробити ця потужність]

## Вигода (задокументовані докази, теми 5.1-5.3)

- [Вигода 1], підтверджена [джерело даних]
- [Вигода 2], підтверджена [джерело даних]

## Діапазон і припущення

- Консервативний сценарій: [значення]
- Оптимістичний сценарій: [значення]
- Ключове припущення, що визначає діапазон: [назвіть його]

## Розглянуті й відкинуті спотворювальні чинники

[Що ще могло б пояснити передбачену вигоду і чому це відкинули чи врахували.]

## Перевірка після завершення (заповніть після завершення ініціативи)

- Фактичний результат: [значення]
- Порівняно з передбаченим діапазоном: [вище / в межах / нижче]
- Чого це нас вчить для наступної оцінки: [примітка]
```
