# 9.3 قوائم التحقق

قوائم تحقق مرجعية سريعة وجاهزة للاستخدام. انسخ واحدة إلى عمليتك الخاصة وكيّفها؛ الهدف هو التغطية، لا الصياغة الدقيقة.

## قائمة تحقق مراجعة مقياس جديد (قبل إضافة أي مقياس للوحة معلومات)

- [ ] للمقياس قرار مُسمًّى يُثريه (الموضوع 1.1)
- [ ] المقياس مُصنَّف كتشخيصي أو تقييمي، خطيًا (الموضوع 1.1)
- [ ] إذا كان مُحفَّزًا، يُحدَّد مقياس ضمان في نفس الوقت (الموضوع 1.2)
- [ ] سُمِّي متجه التلاعب: كيف سيجعل فريق عقلاني هذا الرقم يبدو جيدًا بدون تحسين النتيجة الحقيقية (الموضوع 1.2)
- [ ] المقياس مُصنَّف كمدخل، أو ناتج، أو نتيجة (الموضوع 1.3)
- [ ] للمقياس مالك مُسمًّى ونظام مصدر وطريقة جمع موثقان (الموضوعان 1.4، 1.5)
- [ ] سيستخدم المقياس وسيطًا أو مئينًا، لا متوسطًا، إذا كانت البيانات الأساسية مُنحرِفة (الموضوع 1.6)
- [ ] لا يُستخدَم المقياس أبدًا للتقييم الفردي، أو ذلك الاستخدام مُفصَح عنه بشكل منفصل وصريح (الموضوع 1.1)

## قائمة تحقق إطلاق لوحة معلومات

- [ ] لدى لوحة المعلومات جمهور وقرار محددان ومُسمَّيان (الموضوع 8.1)
- [ ] يظهر كل مقياس مُحفَّز على نفس العرض مع ضمانه (الموضوعان 1.2، 8.1)
- [ ] تبدأ المحاور من الصفر ما لم يُوثَّق استثناء مُصرَّح به ومرئي (الموضوع 1.6)
- [ ] يُعرَض اتجاه عبر الزمن، لا لقطة واحدة (الموضوع 1.6)
- [ ] للوحة المعلومات مالك مُسمًّى ووتيرة مراجعة (الموضوع 1.4)
- [ ] يُعلِن بيان مرئي ما لا تُستخدَم له لوحة المعلومات، إن كان ذا صلة (الموضوع 1.1)
- [ ] لمصادر البيانات فحوصات صحة أساسية بحيث لا يُعرَض خط أنابيب معطل بصمت كحالي (الموضوع 1.5)

## قائمة تحقق طرح برنامج مقاييس

- [ ] يُبلَّغ الغرض وغير الأهداف الصريحة قبل الإطلاق، لا رد فعل (الموضوع 8.3)
- [ ] أُشرِك الأشخاص الذين يُقاسون في اختيار المقياس (الموضوع 8.3)
- [ ] يبدأ البرنامج في وضع تشخيصي فقط، بفترة إثبات دنيا ملتزم بها (الموضوع 8.3)
- [ ] يوجد بروتوكول استجابة سريع ومرئي لأي حادثة سوء استخدام مستقبلية (الموضوع 8.3)
- [ ] اختير فريق تجريبي تطوع حقًا، لا واحد أُلزِم (الموضوع 8.5)
- [ ] الحوكمة التأسيسية (الميثاق، والملكية، والسياسة التشخيصية) موجودة قبل بدء التجهيز بالأدوات (الموضوعان 1.4، 8.5)

## قائمة تحقق حادثة وتشريح ما بعدها

- [ ] يُحقِّق تشريح ما بعد الحادثة في النظام، لا الفرد (الموضوع 6.2)
- [ ] صُنِّفت الخطورة مقابل معايير موثقة وموحّدة (الموضوع 6.2)
- [ ] سُجِّلت أوقات الكشف، والإقرار، والحل بشكل منفصل (الموضوع 6.2)
- [ ] عناصر الإجراء محددة، ومُسنَدة، ومُتَبَّعة حتى الاكتمال (الموضوع 6.2)
- [ ] يُشارَك تشريح ما بعد الحادثة بدون خوف من عاقبة فردية (الموضوعان 6.2، 8.3)

## قائمة تحقق تدقيق مقياس عصر الذكاء الاصطناعي

- [ ] اُختُبِر كل مقياس لوحة معلومات مقابل: "هل سيُظهر فريق يستخدم مساعدة ذكاء اصطناعي بكثافة لكن لا يُنتج قيمة حقيقية أكثر قراءة مُحسَّنة هنا" (الموضوع 7.1)
- [ ] يُراجَع معدل فشل التغيير ومعدل العيوب إلى جانب أي ارتفاع في تكرار نشر أو حجم التزام مدعوم بالذكاء الاصطناعي (الموضوع 7.1)
- [ ] تُراقَب قدرة المراجعة وعمقها مع تغيّر حجم الكود المُولَّد بالذكاء الاصطناعي (الموضوع 7.1)
- [ ] تُصنَّف العيوب المتسربة حسب مستوى مساعدة الذكاء الاصطناعي لاختبار، لا افتراض، ما إذا كانت علاقة معدل العيوب التاريخية لا تزال قائمة (الموضوعان 7.1، 7.3)
- [ ] طرق اكتشاف مقاومة لعيوب "يبدو صحيحًا" (اختبار الطفرات، والاختبار القائم على الخصائص) موجودة لمسارات كود كثيفة الذكاء الاصطناعي (الموضوع 7.3)
- [ ] أُعيدَت زيارة ميثاق المقاييس صراحة وحُدِّث لهذا التحول، لا تُرِك للانجراف بلا فحص (الموضوعان 1.4، 7.1)

## قائمة تحقق تدقيق برنامج مقاييس (سنوي)

- [ ] لا يزال لكل مقياس مالك مُسمًّى (الموضوع 1.4)
- [ ] تقاعد مقياس واحد على الأقل في الدورة الأخيرة إن توقف عن تحقيق قيمته (الموضوع 1.1)
- [ ] أُجرِي تقييم النضج خماسي الأبعاد بصدق، مُسجَّلًا بالحد الأدنى، لا المتوسط (الموضوع 8.4)
- [ ] لم ينجرف أي مقياس من استخدام تشخيصي إلى تقييمي بدون قرار صريح ومُفصَح عنه (الموضوع 1.1)
- [ ] دُقِّقت التعريفات عينيًا مقابل الأدوات القياسية الفعلية للانجراف (المواضيع 1.2، 2.4، 5.1، 6.2، 6.4)
- [ ] حُسِبَت وروجِعَت نسبة النتيجة إلى الناتج على لوحات المعلومات الأساسية (الموضوع 7.4)
