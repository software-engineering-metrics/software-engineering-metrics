# উদাহরণ: একটি পেমেন্ট প্ল্যাটফর্ম দলের জন্য মেট্রিক সনদ

একটি মেট্রিক সনদের কার্যকর উদাহরণ, যে এক পাতার নথির কথা
[বিষয় ১.৪, মেট্রিক শাসনব্যবস্থা ও মালিকানা](../chapters/01-04-মেট্রিক-গভর্নেন্স-ও-মালিকানা.md)-এ
বর্ণিত। মূল কথা আকারটি: একটি ঘোষিত উদ্দেশ্য, একটি স্পষ্ট অ-লক্ষ্য, নামধারী মালিক এবং একটি পর্যালোচনা
চক্র। এত ছোট একটি সনদ পড়ার জন্য, ফাইলে তুলে রাখার জন্য নয়।

- **দল:** পেমেন্ট প্ল্যাটফর্ম
- **মালিক:** প্ল্যাটফর্ম ইঞ্জিনিয়ারিং ম্যানেজার
- **পর্যালোচনা:** ত্রৈমাসিক, প্ল্যাটফর্ম পর্যালোচনায়

## উদ্দেশ্য

এই সনদ পেমেন্ট প্ল্যাটফর্ম দল নিজের সরবরাহ ও নির্ভরযোগ্যতা নিয়ে যে মেট্রিক অনুসরণ করে তা নিয়ন্ত্রণ
করে। এটি আছে যাতে দলের ভেতরের ও বাইরের সবাই দেখতে পারে কী মাপা হয়, কেন, এবং কীসের জন্য নয়।

## আমরা কী অনুসরণ করি

| মেট্রিক | সত্যের উৎস | মালিক |
| --- | --- | --- |
| স্থাপনার ফ্রিকোয়েন্সি | CI/CD পাইপলাইন | প্ল্যাটফর্ম লিড |
| পরিবর্তনের লিড টাইম | Git সহ স্থাপনা পাইপলাইন | প্ল্যাটফর্ম লিড |
| পরিবর্তন ব্যর্থতার হার | ঘটনা ট্র্যাকার, স্থাপনা অনুযায়ী ট্যাগ করা | অন-কল লিড |
| ব্যর্থ স্থাপনা থেকে পুনরুদ্ধারের সময় | ঘটনা ট্র্যাকার | অন-কল লিড |
| P99 API লেটেন্সি (SLI) | অবজার্ভেবিলিটি প্ল্যাটফর্ম | SRE লিড |
| ত্রুটি বাজেট ক্ষয় | অবজার্ভেবিলিটি প্ল্যাটফর্ম | SRE লিড |

## অ-লক্ষ্য

এই মেট্রিকগুলো কখনোই, এককভাবে বা সম্মিলিতভাবে, ইঞ্জিনিয়ারদের র‍্যাঙ্ক করতে, কর্মক্ষমতা পর্যালোচনা
মূল্যায়ন করতে, বা পরিধি, কর্মীসংখ্যা ও সিস্টেমের পরিপক্বতাও তুলনা না করে এই দলকে অন্য দলের
রোডম্যাপের সাথে তুলনা করতে ব্যবহার হয় না। উপরে ঘোষিত উদ্দেশ্যের বাইরে যেকোনো ব্যবহারে প্রকৌশল
পরিচালক এবং দল নিজে, উভয়ের অনুমোদন প্রয়োজন।

## গার্ডরেল

উপরের যেসব মেট্রিকে প্রণোদনা আছে প্রতিটির সাথে একটি গার্ডরেল জোড়া। পরিবর্তনের লিড টাইম দেখা হয়
পরিবর্তন ব্যর্থতার হারের পাশে, যাতে দল ঝুঁকিপূর্ণ পরিবর্তন পাঠিয়ে গতির সংখ্যা উন্নত করতে না পারে।
স্থাপনার ফ্রিকোয়েন্সি দেখা হয় ত্রুটি বাজেট ক্ষয়ের পাশে, একই কারণে।

## পর্যালোচনা চক্র

দল প্রতি ত্রৈমাসিকে এই সনদ পর্যালোচনা করে। পরপর দুই ত্রৈমাসিকে যে মেট্রিক কোনো সিদ্ধান্ত বদলায়নি
সেটি অবসরের প্রার্থী।
