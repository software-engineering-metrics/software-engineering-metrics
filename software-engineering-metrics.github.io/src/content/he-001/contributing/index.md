# תרומה

תודה שאתם עוזרים לשפר את הספר. תרומות מכל גודל מתקבלות בברכה, מתיקון שגיאת כתיב ועד כתיבת נושא חדש.

## כללי יסוד

הספר פועל לפי סגנון בית קפדני. העיקר:

- בלי מקפים ארוכים. השתמשו בפסיק, בנקודתיים, בסוגריים או בשני משפטים.
- בלי ניסוחי סרק ("not only ... but also", "load-bearing" וכדומה).
- כתיבה חמה, פשוטה וישירה. פונים לקורא בגוף שני. משפטים קצרים.
- מגדירים מונחים בשימוש הראשון. מקשרים מושגי מפתח לוויקיפדיה באזכור הראשון.
- מקורות אמיתיים בלבד.
- כל נושא שעוסק במשפחת מדדים מציין את וקטור המניפולציה שלו ואת מעקה הבטיחות שלו.

הכללים המלאים נמצאים ב-`spec/conventions.md` בשורש המאגר, והגרסה הקצרה היא [כללי הסגנון](style-rules.md). הבדיקות אוכפות את החלקים המכניים.

## הגדרה

צריך Python 3 ואת [just](https://github.com/casey/just). המאגר הזה מכיל את תוכן הספר ואת המפרט שלו, וגם את אתר SvelteKit (`software-engineering-metrics.github.io/`) שמציג אותו כאתר המפורסם.

```sh
just         # list tasks
just test    # run the validation suite
just nav     # regenerate the generated navigation files
just stats   # topic and word counts
```

## ביצוע שינוי

1. קראו את המדריך הרלוונטי: [כתיבה](authoring.md) לנושאים, [ניווט](navigation.md) לקבצים שנוצרים אוטומטית, [בדיקות](testing.md) לבדיקות.
2. בצעו את השינוי הקטן ביותר שעושה את העבודה.
3. אם הוספתם, הסרתם, שיניתם שם או מספר של נושא, עדכנו את `spec/structure.md` בשורש המאגר והריצו `just nav`.
4. הריצו `just test`. הוא חייב לעבור.
5. הוסיפו שורה אחת ל[יומן השינויים](../project/changelog.md) תחת **Unreleased**.

## על מה לעבוד

- לתקן שגיאות, קטעים לא ברורים או מקורות מיושנים.
- לשפר דוגמאות, בעיקר דוגמאות קונקרטיות מארגונים גדולים ומגופים ממשלתיים.
- לאמת ציטוטים מול מקורות אמיתיים.
- למלא פערים בכיסוי של נושא בלי לשבור את התבנית.

## ממה להימנע

- אל תערכו ביד את הקבצים שנוצרים אוטומטית (`README.md`, ה-`index.md` של כל לוקאל, `front-matter/table-of-contents.md` ו-`topics/09-07-index.md`). שנו את הנושאים והריצו `just nav`.
- אל תערכו ישירות את `en-001`, `en-gb` או `en-us`; הם נגזרים מ-`en-gb-oxendict` בעזרת `tools/localize.py`.
- אל תוסיפו נושא בלי לעדכן גם את `spec/structure.md`.
- אל תכניסו מקפים ארוכים או ניסוחים אסורים; הבדיקות ייכשלו.

## דיווח על בעיות

פתחו issue שמתאר את הבעיה, את הקובץ ואת הנושא, ובמקרה הצורך את המקור או ההפניה הנכונים. דיווחים קטנים וספציפיים הם הקלים ביותר לטיפול.
