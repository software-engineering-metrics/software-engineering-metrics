# 例: デリバリー指標ダッシュボードのダッシュボード仕様

ダッシュボード仕様の具体例で、[トピック8.1、エンジニアリング指標ダッシュボードの設計](../chapters/08-01-エンジニアリング指標ダッシュボードの設計.md)
に沿っています。要点はその形です。名前のある対象者、少数のタイル、誠実な可視化の基準、明示された更新周期。

## 対象者

エンジニアリングのリーダーシップとプラットフォームチームで、隔週のデリバリーレビューで見られます。個人のパフォーマンス評価には使いません。

## タイル(表示順)

1. **デプロイ頻度**、直近4週間、チーム別。折れ線グラフ、週単位のバケット、軸はゼロから始まります。
2. **変更のリードタイム**、中央値と90パーセンタイル、直近4週間。中央値だけでなく両方の系列を示す棒グラフ。
3. **変更失敗率**、直近4週間、チームが合意した「失敗」の定義へタイルからリンク。
4. **失敗したデプロイからの復旧時間**、中央値、直近4週間。
5. **残りのエラーバジェット**、今四半期、サービスごと、パーセンテージで。

## 可視化のルール

- すべてのトレンドチャートは少なくとも8つのデータ点を示し、単一のスナップショットは決して使いません。
- タイルに明示された例外が文書化されていない限り、軸はゼロから始まります。
- デプロイ、インシデント、祝日をタイムラインに注釈し、読み手が本当の変化とノイズを見分けられるようにします。
- 二重軸なし、3-D効果なし、都合のよい日付範囲の選び取りなし。

## 更新周期

パイプライン由来のタイル(デプロイ頻度、リードタイム)は1時間ごとに更新されます。インシデント由来のタイル
(変更失敗率、復旧時間)はポストモーテムの完了時に更新されます。ダッシュボードは自らの最終更新時刻を表示します。

## このダッシュボードが意図的に除外するもの

個人のコミット数、個人のプルリクエスト数、コード行数。これらは、操作されてきた経緯が十分に記録され、
アウトカムではなく労力を測るアクティビティ指標です(トピック3.4)。
