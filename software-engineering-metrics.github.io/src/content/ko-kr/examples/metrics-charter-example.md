# 예시: 결제 플랫폼 팀의 메트릭 헌장

메트릭 헌장의 구체적인 예시로, [주제 1.4, 메트릭 거버넌스와 소유권](../chapters/01-04-메트릭-거버넌스와-소유권.md)에서 설명한 한 쪽짜리 문서다.
핵심은 형태다. 명시된 목적, 분명한 비목적, 이름이 있는 소유자, 검토 주기. 이렇게 짧은 헌장은 서랍에 넣어 두려는 것이 아니라 읽히려고 만든 것이다.

- **팀:** 결제 플랫폼
- **소유자:** 플랫폼 엔지니어링 매니저
- **검토:** 분기마다, 플랫폼 리뷰에서

## 목적

이 헌장은 결제 플랫폼 팀이 자신의 전달과 신뢰성에 대해 추적하는 메트릭을 관장한다. 팀 안팎의 누구나 무엇이 왜 측정되는지, 그리고 무엇에 쓰이지 않는지 볼 수 있도록 존재한다.

## 우리가 추적하는 것

| 메트릭 | 신뢰할 수 있는 원천 | 소유자 |
| --- | --- | --- |
| 배포 빈도 | CI/CD 파이프라인 | 플랫폼 리드 |
| 변경 리드 타임 | Git과 배포 파이프라인 | 플랫폼 리드 |
| 변경 실패율 | 인시던트 트래커, 배포별로 태그 | 온콜 리드 |
| 실패한 배포로부터의 복구 시간 | 인시던트 트래커 | 온콜 리드 |
| P99 API 지연(SLI) | 관측 가능성 플랫폼 | SRE 리드 |
| 에러 버짓 소진 | 관측 가능성 플랫폼 | SRE 리드 |

## 비목적

이 메트릭은 개별로든 결합으로든 엔지니어의 순위를 매기거나, 성과 평가를 판단하거나, 범위, 인원, 시스템 성숙도를 함께 비교하지 않은 채
이 팀을 다른 팀의 로드맵과 비교하는 데 쓰이지 않는다. 위에 밝힌 목적 밖의 어떤 사용도 엔지니어링 디렉터와 팀 자신의 승인이 필요하다.

## 가드레일

위에서 인센티브가 걸린 모든 메트릭은 가드레일과 짝지어져 있다. 변경 리드 타임은 변경 실패율과 함께 감시되므로, 팀이 더 위험한 변경을 내보내서
속도 수치를 개선할 수 없다. 배포 빈도는 같은 이유로 에러 버짓 소진과 함께 감시된다.

## 검토 주기

팀은 이 헌장을 분기마다 검토한다. 두 분기 연속으로 어떤 결정도 바꾸지 못한 메트릭은 은퇴 후보다.
