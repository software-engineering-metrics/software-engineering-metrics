# 9.4 Шаблоны

Шаблоны для копирования и вставки для повторяющихся документов. Отработанные, заполненные примеры первых двух находятся в `docs/examples/`.

## Шаблон устава метрик

```markdown
# Устав метрик: [название команды или набора метрик]

- **Команда:** [владеющая команда]
- **Владелец:** [именованный человек или роль]
- **Пересматривается:** [каденция, например ежеквартально]

## Цель

[Одно или два предложения: что управляет этот устав и почему.]

## Что мы отслеживаем

| Метрика | Источник истины | Владелец |
| --- | --- | --- |
| [метрика] | [система] | [именованный владелец] |

## Не-цели

[Явное заявление о том, для чего эти метрики не используются, например
индивидуальная оценка производительности, межкомандное ранжирование без контекста.]

## Страховочные метрики

[Для каждой стимулируемой метрики назовите её сочетанную страховочную метрику
и какой паттерн манипулирования она ловит.]

## Каденция пересмотра

[Когда и как этот устав пересматривается; что вызывает вывод метрики из эксплуатации.]
```

## Шаблон спецификации панели

```markdown
# Спецификация панели: [название панели]

## Аудитория

[Для кого эта панель, и какое решение она информирует. Явно укажите,
если не для индивидуальной оценки.]

## Плитки (в порядке отображения)

1. **[Название метрики]**, [временное окно], [тип диаграммы]. [Любые конкретные
   заметки визуализации: правила осей, аннотации.]
2. ...

## Правила визуализации

- Оси начинаются с нуля, если не заявлено иное, с исключением,
  задокументированным на плитке.
- [Любые другие правила честности, специфичные для проекта.]

## Каденция обновления

[Как часто обновляется каждая плитка, и из какого источника.]

## Что эта панель сознательно исключает

[Назовите всё намеренно опущенное, и почему, например индивидуальные
счётчики активности.]
```

## Шаблон повестки встречи пересмотра метрик

```markdown
# Пересмотр метрик: [дата]

## Участники

[Имена и роли]

## Пересмотренные метрики

Для каждой метрики:
- Текущее показание и тренд
- Любое движение за пределами нормальной вариации (глава 1.6)
- Статус сочетанной страховочной метрики, если применимо
- Решение, которое информирует это показание, если таковое есть

## Предложенные новые метрики

[Пропустите каждую через чек-лист пересмотра новой метрики, глава 9.3.]

## Метрики, рассматриваемые для вывода из эксплуатации

[Какие метрики не информировали решение за последние два цикла?]

## Пункты действий

| Пункт | Владелец | Срок |
| --- | --- | --- |
| | | |
```

## Шаблон безвиновного разбора инцидента

```markdown
# Разбор инцидента: [название инцидента], [дата]

## Краткое содержание

[Один абзац: что произошло, воздействие на пользователя, длительность.]

## Хронология

- Обнаружение: [время, как обнаружено]
- Подтверждение: [время, кто отреагировал]
- Решение: [время, что это исправило]

## Серьёзность

[Классификация против задокументированных критериев, глава 6.2.]

## Первопричина

[Что позволило этому произойти, сформулированное как системный вопрос,
а не индивидуальный.]

## Что прошло хорошо

[Конкретные вещи, сработавшие в реагировании.]

## Пункты действий

| Пункт | Владелец | Срок |
| --- | --- | --- |
| | | |

## Последующее наблюдение

[Подтверждение того, что пункты действий отслеживались до завершения,
согласно следующему циклу пересмотра.]
```

## Шаблон кейса ROI

```markdown
# Кейс ROI: [название инициативы]

## Стоимость (полная стоимость владения, глава 5.5)

- Первоначальная: [стоимость разработки]
- Постоянная: [обслуживание, инфраструктура, поддержка, в год]
- Альтернативная стоимость: [что ещё могла бы сделать эта мощность]

## Выгода (задокументированное доказательство, главы 5.1–5.3)

- [Выгода 1], подтверждённая [источником данных]
- [Выгода 2], подтверждённая [источником данных]

## Диапазон и предположения

- Консервативный случай: [цифра]
- Оптимистичный случай: [цифра]
- Ключевое предположение, движущее диапазоном: [назовите его]

## Рассмотренные и исключённые искажающие факторы

[Что ещё могло бы объяснить спроецированную выгоду, и почему это было
исключено или учтено.]

## Проверка после завершения (заполните после завершения инициативы)

- Фактический результат: [цифра]
- Сравнение со спроецированным диапазоном: [выше / в рамках / ниже]
- Чему это учит нас для следующей оценки: [заметка]
```
