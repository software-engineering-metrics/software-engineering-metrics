# 3.4 ตัวชี้วัดกิจกรรมและข้อจำกัด

## ภาพรวมและแรงจูงใจ

**กิจกรรม (Activity)** ซึ่งก็คือตัว A ใน SPACE (หัวข้อ 3.1) นับปริมาณงานวิศวกรรมที่สังเกตได้จาก telemetry ของระบบ
ได้แก่ commit pull request ที่เปิด จำนวนบรรทัดโค้ดที่เปลี่ยน และความเห็นในการรีวิวโค้ดที่ทิ้งไว้
เป็นมิติของ SPACE ที่วัดง่ายที่สุด เพราะเหตุการณ์เหล่านี้ทุกอย่างถูกบันทึกอัตโนมัติอยู่แล้วโดยเครื่องมือที่ทีมวิศวกรรมใช้ทุกวัน
และความง่ายในการวัดนี้เองคือสิ่งที่ทำให้มิตินี้อันตรายที่สุดหากให้น้ำหนักมากเกินไป
กิจกรรมเป็นสัญญาณจริงที่ชอบธรรมเมื่อใช้อย่างระมัดระวัง แต่เมื่อใช้เป็นตัวแทนผลิตภาพเดี่ยว ๆ
มันคือตระกูลตัวชี้วัดที่ถูกเล่นแร่แปรธาตุมากที่สุดและชี้นำผิดมากที่สุดในประวัติศาสตร์การวัด[วิศวกรรมซอฟต์แวร์](https://en.wikipedia.org/wiki/Software_engineering)ทั้งหมด

ปัญหาหลักคือกิจกรรมวัดการเคลื่อนไหว ไม่ใช่คุณค่า จำนวน commit แยกไม่ออกระหว่าง commit ที่แก้ปัญหายากได้อย่างสง่างาม
กับ commit ที่แบ่งการเปลี่ยนแปลงที่มีความหมายหนึ่งอย่างออกเป็นห้าส่วนเพื่อให้ดูมีผลิตภาพขึ้น
(การเล่นแร่แปรธาตุแบบการแทนที่ของหัวข้อ 1.2 ที่ใช้กับตระกูลตัวชี้วัดนี้โดยตรง)
จำนวนบรรทัดที่เปลี่ยนให้รางวัลแก่ความเยิ่นเย้อ แทนที่จะเป็นทักษะที่มีค่ากว่ามากคือการลบโค้ดที่ไม่จำเป็น
วิศวกรที่ใช้เวลาทั้งวันครุ่นคิดอย่างลึกซึ้งโดยไม่ถูกขัดจังหวะ ก่อนเขียนโค้ดสิบบรรทัดที่สง่างามและทดสอบดี
ดู "กระตือรือร้น" น้อยกว่าคนที่ commit การเปลี่ยนแปลงตื้น ๆ ที่ไม่ผ่านการรีวิวทุกยี่สิบนาทีตามตัวชี้วัดเหล่านี้
ทั้งที่คนแรกมักสร้างคุณค่าจริงมากกว่ามาก

สำหรับทีมขนาดใหญ่ ความล่อใจที่จะใช้ตัวชี้วัดกิจกรรมประเมินรายบุคคลมีอยู่ตลอดเวลาและมีบันทึกชัดเจน
เพราะกิจกรรมระบุเป็นของบุคคลเฉพาะคนได้ง่ายและคำนวณอัตโนมัติได้ง่าย ต่างจากสัญญาณที่ยากกว่าและตรงไปตรงมากว่าในมิติอื่นของ SPACE
หัวข้อนี้มีขึ้นโดยเฉพาะเพื่อเอ่ยถึงความล่อใจนั้นและให้ทีมมีภาษาและหลักฐานต้านมัน
เพราะเมื่อองค์กรเริ่มจัดอันดับวิศวกรรายบุคคลด้วยจำนวน commit หรือจำนวนบรรทัดโค้ด ความเสียหายต่อการร่วมมือ คุณภาพโค้ด และขวัญกำลังใจมีบันทึกไว้ชัดและย้อนกลับยาก

## หลักการสำคัญ

- **กิจกรรมวัดการเคลื่อนไหว ไม่ใช่คุณค่า** เป็นสัญญาณบริบทที่ชอบธรรม ไม่เคยเป็นตัวแทนผลิตภาพเดี่ยว
- **นี่คือตระกูลตัวชี้วัดที่ถูกใช้ผิดมากที่สุดในประวัติศาสตร์การวัดวิศวกรรมซอฟต์แวร์**
  ถือประวัติศาสตร์นั้นเป็นคำเตือน ไม่ใช่เรื่องบังเอิญ
- **การจัดอันดับกิจกรรมรายบุคคลเป็นอันตรายเกือบทุกครั้ง** ทำลายการร่วมมือ ให้รางวัลงานยุ่งที่มองเห็นได้
  และเชิญชวนการเล่นแร่แปรธาตุเกือบทันที
- **ข้อมูลกิจกรรมมีประโยชน์ที่สุดในรูปผลรวม เป็นบริบทให้มิติอื่น**
  ไม่ใช่สัญญาณอิสระเกี่ยวกับบุคคลหรือทีมใดทีมหนึ่ง
- **งานเชิงลึกที่มีคุณค่ามักดูเงียบบนแดชบอร์ดกิจกรรม**
  ตระกูลตัวชี้วัดนี้ลำเอียงเชิงโครงสร้างต่อการคิดแบบที่สร้างผลลัพธ์ด้านวิศวกรรมที่ดีที่สุดพอดี

## ข้อเสนอแนะ

### อย่าจัดอันดับหรือประเมินรายบุคคลด้วยจำนวนกิจกรรมดิบ

นี่คือกฎที่ยากที่สุดและสำคัญที่สุดของหัวข้อนี้ จำนวน commit จำนวนบรรทัดโค้ด และจำนวน pull request
ไม่ควรปรากฏในการประเมินผลงานรายบุคคล การจัดอันดับเปรียบเทียบ หรือบริบทใด ๆ ที่ค่าตอบแทน สถานะ หรือชื่อเสียงของวิศวกรขึ้นอยู่กับตัวเลขนั้น
สิ่งนี้เป็นไปตามหลักการการเปิดรับแรงจูงใจของหัวข้อ 1.2 โดยตรง
คือเมื่อกิจกรรมกลายเป็นตัวชี้วัดรายบุคคลที่มีสิ่งจูงใจ การเล่นแร่แปรธาตุตามมาเกือบทันที
และพฤติกรรมที่เกิดขึ้น ได้แก่ การถม commit การแบ่งการเปลี่ยนแปลงเป็นชิ้นเล็กไร้ความหมาย
การเลี่ยงงานเชิงลึกที่ไม่หรูหราซึ่งสร้างเหตุการณ์ที่มองเห็นได้น้อย ล้วนทำร้ายองค์กรอย่างแข็งขัน

### ใช้ข้อมูลกิจกรรมในรูปผลรวม เป็นบริบท ไม่ใช่คำตัดสิน

ข้อมูลกิจกรรมมีประโยชน์จริงเมื่อรวมที่ระดับทีมและอ่านควบคู่กับมิติอื่นของ SPACE
กิจกรรม commit ระดับทีมที่ลดฮวบพร้อมกับความพึงพอใจที่เพิ่มขึ้น อาจบ่งว่าทีมได้มีที่หายใจเพื่อคิดอย่างลึกซึ้งและชำระหนี้ทางเทคนิคเสียที
เป็นรูปแบบเชิงบวก ไม่ใช่เชิงลบ หากอ่านโดดเดี่ยว การลดลงเดียวกันดูน่าตกใจ
บริบทจากมิติอื่นคือสิ่งที่ทำให้ข้อมูลกิจกรรมตีความได้แทนที่จะชี้นำผิด

### เลือกสัญญาณกิจกรรมที่ใกล้เคียงคุณภาพแทนปริมาณดิบ

ในที่ที่ข้อมูลกิจกรรมมีประโยชน์ ให้เลือกสัญญาณที่ปรับด้วยคุณภาพแล้วแทนจำนวนดิบ
เช่น ขนาด pull request เทียบกับความลึกของการรีวิว (หัวข้อ 2.9)
หรืออัตราส่วนของโค้ดใหม่ต่อโค้ดที่ถูกลบ ซึ่งเผยได้ว่าทีมกำลังสะสมความซับซ้อนหรือกำลังทำให้เรียบง่ายขึ้นอย่างแข็งขัน
สัญญาณที่ปรับแล้วเหล่านี้ยังเป็นข้อมูลของมิติกิจกรรม แต่ต้านการเล่นแร่แปรธาตุแบบหยาบที่สุดที่จำนวนดิบเชื้อเชิญได้

### จับตารูปแบบการเล่นแร่แปรธาตุแบบการแทนที่ในข้อมูลกิจกรรมโดยเฉพาะ

วิธีที่พบบ่อยที่สุดที่ตัวชี้วัดกิจกรรมถูกเล่นแร่แปรธาตุ คือรูปแบบการแทนที่ของหัวข้อ 1.2 พอดี
คือแบ่งงานที่มีความหมายจริงออกเป็นเหตุการณ์เล็กไร้สาระจำนวนมากเพื่อปั่นจำนวน
หากความถี่ของ commit หรือ pull request สูงขึ้นขณะที่ความซับซ้อนหรือขนาดของการเปลี่ยนแปลงลดลงฮวบ
ให้สืบสวนก่อนจะให้เครดิตว่าผลิตภาพดีขึ้นจริง ใช้วินัยการวินิจฉัยเดียวกับที่หัวข้อ 2.10 แนะนำสำหรับ deployment frequency

### เอ่ยถึงและห้ามปรามการแสดงละครกิจกรรมอย่างชัดแจ้ง

**การแสดงละครกิจกรรม (activity theater)** คืองานที่ทำ ด้วยความตั้งใจหรือไม่ก็ตาม
เป็นหลักเพราะมองเห็นและนับได้ ไม่ใช่เพราะมีคุณค่า เช่น commit เล็ก ๆ บ่อย ๆ
กิจกรรมดึกดื่นที่เด่นชัด หรือความยุ่งที่มองเห็นได้ในช่องทางสื่อสารร่วม
การเอ่ยถึงรูปแบบนี้กับทีมอย่างชัดแจ้ง และโปร่งใสว่าผู้นำไม่ใช้กิจกรรมดิบตัดสินการมีส่วนร่วม
ขจัดแรงจูงใจให้เกิดขึ้นตั้งแต่แรกไปได้มาก

## ข้อแลกเปลี่ยน: ข้อดีและข้อเสีย

| แนวทาง | ข้อดี | ข้อเสีย |
| --- | --- | --- |
| จัดอันดับกิจกรรมรายบุคคล | ง่าย คำนวณง่าย รู้สึกว่านำไปปฏิบัติได้ทันที | ถูกเล่นแร่แปรธาตุเกือบทันที ทำลายการร่วมมือและขวัญกำลังใจ วัดผิดสิ่ง |
| ไม่วัดกิจกรรมเลย | หลีกเลี่ยงความเสี่ยงการใช้ผิดโดยสิ้นเชิง | เสียสัญญาณบริบทที่มีประโยชน์จริงสำหรับการสังเกตรูปแบบระดับทีม |
| กิจกรรมรวมระดับทีม อ่านตามบริบท | ให้บริบทที่มีประโยชน์โดยไม่เสี่ยงต่อรายบุคคล | ต้องมีวินัยตีความควบคู่มิติอื่นแทนที่จะแยกเดี่ยว |
| สัญญาณกิจกรรมที่ปรับด้วยคุณภาพ | ต้านการเล่นแร่แปรธาตุจำนวนดิบแบบหยาบที่สุด | คำนวณและอธิบายซับซ้อนกว่าจำนวนธรรมดา |

ความตึงเครียดหลักคือ **ประโยชน์เทียบกับความเสี่ยงการใช้ผิด**
ข้อมูลกิจกรรมที่อ่านอย่างระมัดระวังในรูปผลรวมและตามบริบทมีประโยชน์จริงในการสังเกตรูปแบบ
เช่น จังหวะงานที่ไม่ยั่งยืน หรือทีมที่เงียบ ๆ หาที่ว่างจัดการหนี้ทางเทคนิค
ข้อมูลเดียวกันที่ใช้เป็นใบคะแนนรายบุคคลเป็นอันตรายแทบทุกกรณี
แก้ความตึงเครียดนี้ไม่ใช่ด้วยการหลีกเลี่ยงข้อมูลกิจกรรมทั้งหมด
แต่ด้วยการสร้างกฎองค์กรที่เด็ดขาดห้ามใช้ระดับบุคคล พร้อมอนุญาตและสนับสนุนการใช้ระดับทีมที่ไตร่ตรองและมีบริบท

## คำถามเพื่อหารือกับทีมของคุณ

1. **เคยมีใครในองค์กรของเราถูกประเมิน ทั้งแบบเป็นทางการหรือไม่เป็นทางการ ด้วยจำนวนกิจกรรมดิบอย่าง commit หรือจำนวนบรรทัดโค้ดหรือไม่?**
   ถามตรง ๆ และเตรียมรับคำตอบที่อึดอัดแต่จำเป็น การใช้ผิดแบบนี้มักเกิดอย่างเงียบ ๆ ผ่านความเห็นผ่านหูของผู้จัดการ
   โดยไม่เคยเป็นนโยบายทางการ

2. **การแสดงละครกิจกรรมจะหน้าตาอย่างไรในทีมของเราโดยเฉพาะ และเราเคยเห็นร่องรอยของมันหรือไม่?**
   การเอ่ยถึงรูปแบบที่เป็นไปได้จริงที่รูปแบบนี้อาจมีในทีมของคุณเอง ทำให้จำได้ง่ายขึ้นมากหากมันเริ่มเกิดขึ้น

3. **เมื่อข้อมูลกิจกรรมระดับทีมของเราขยับ เราตีความควบคู่กับมิติอื่นของ SPACE หรือแยกเดี่ยว?**
   กิจกรรมที่ลดลงเมื่ออ่านโดดเดี่ยวดูน่ากังวล แต่การลดลงเดียวกันเมื่ออ่านควบคู่กับความพึงพอใจหรือประสิทธิภาพที่ดีขึ้น
   อาจดูเป็นรูปแบบเชิงบวกจริง ๆ ตรวจวิธีทบทวนจริงของคุณเทียบกับความแตกต่างนี้

4. **เราเคยเห็นความถี่ของ commit หรือ pull request เพิ่มขึ้นพร้อมขนาดการเปลี่ยนแปลงเฉลี่ยที่หดลง ซึ่งบ่งถึงการแบ่งเป็นชิ้นเล็กไร้ความหมายแทนผลิตภาพที่เพิ่มขึ้นจริงหรือไม่?**
   ดึงข้อมูลจริงมาตรวจหารูปแบบการเล่นแร่แปรธาตุแบบการแทนที่นี้โดยเฉพาะ

5. **ตอนนี้เราพูดถึง "ใครมีส่วนมากที่สุด" ในทีมอย่างไร และบทสนทนานั้นเอนไปพึ่งข้อมูลกิจกรรมโดยปริยายแม้ไม่มีตัวชี้วัดทางการหรือไม่?**
   อคติที่ไม่เป็นทางการและไม่ได้วัดต่อความยุ่งที่มองเห็นได้ ก่อรูปการรับรู้และรางวัลได้แม้ไม่มีนโยบายกิจกรรมที่ชัดแจ้ง ลองเผยเรื่องนี้ตามจริง

6. **งานที่มีคุณค่าจริงแต่เงียบ เช่น การคิดเชิงลึก การออกแบบอย่างรอบคอบ การเป็นพี่เลี้ยง หน้าตาเป็นอย่างไรในทีมของเรา และเราจะแน่ใจได้อย่างไรว่ามันได้รับการยอมรับแม้สร้างข้อมูลกิจกรรมให้เห็นน้อย?**
   คำถามนี้เป็นส่วนเติมเต็มเชิงบวกของข้อก่อนหน้า การเอ่ยถึงว่างานเงียบที่ดีหน้าตาเป็นอย่างไรช่วยปกป้องมันจากการถูกมองข้ามเพราะงานที่เสียงดังและนับได้มากกว่า

## มุมมองตามภาคส่วน

**สตาร์ทอัป** กับทีมเล็กที่ร่วมมือกันแน่นแฟ้น ข้อมูลกิจกรรมมักมองเห็นได้โดยไม่ต้องมีแดชบอร์ดเลย
และความเสี่ยงของการจัดอันดับรายบุคคลที่หัวข้อนี้เตือนก็มีโอกาสน้อยกว่า เพราะทุกคนรู้อยู่แล้วว่าคนอื่นทำอะไร
ความเสี่ยงกลับเป็นผู้ก่อตั้งที่โน้มเอียงโดยไม่รู้ตัวไปทางพฤติกรรมที่ดู "ยุ่ง" ตอนตัดสินใจเรื่องการจ้างหรือหุ้นช่วงต้น

**ธุรกิจขนาดเล็ก** การชำเลืองดูข้อมูลกิจกรรมจากเครื่องมือที่มีอยู่เพื่อให้เห็นภาพรวมของ throughput ทีมนั้นไม่เป็นไร
แต่อย่าใช้เปรียบเทียบผู้ร่วมงานรายบุคคลโดยตรง คุณค่าจริงของทีมเล็กมักกระจุกอยู่ที่คนไม่กี่คนที่ทำงานเงียบ ๆ แต่มีแรงส่งสูง
ซึ่งมุมมองจำนวน commit จะประเมินต่ำกว่าจริงอย่างเป็นระบบ

**องค์กรขนาดใหญ่** ที่นี่คือที่ที่ความล่อใจจัดอันดับรายบุคคลแรงและสร้างความเสียหายที่สุด
เพราะข้อมูลกิจกรรมคือสัญญาณที่ดึงง่ายที่สุดสำหรับกระบวนการประเมินผลงานที่ครอบคลุมวิศวกรหลายพันคน
และแรงกดดันที่จะหาปัจจัยนำเข้าที่ "วัดเป็นตัวเลขได้" สักอย่างนั้นมีอยู่จริง
สร้างนโยบายที่ชัดแจ้ง สื่อสาร และบังคับใช้ ต่อต้านการจัดอันดับกิจกรรมรายบุคคล
และตรวจสอบแนวปฏิบัติการประเมินผลงานเป็นระยะเพื่อยืนยันว่านโยบายถูกปฏิบัติตามจริง ไม่ใช่แค่ประกาศ

**ภาครัฐ** ตัวชี้วัดกิจกรรมอาจล่อใจให้อ้างในรายงานสาธารณะเป็นหลักฐานของผลิตภาพ ("หนึ่งหมื่น commit ในปีนี้")
แต่พาดหัวแบบนี้แทบไร้ความหมาย และอาจเชิญชวนการตรวจสอบผิดแบบเมื่อผู้ตรวจที่รู้เรื่องชี้ว่ากิจกรรมดิบบอกอะไรเกี่ยวกับผลลัพธ์ไม่ได้เลย
รายงานข้อมูลผลลัพธ์และประสิทธิภาพ (หัวข้อ 3.3) แทน และหลีกเลี่ยงจำนวนกิจกรรมในการสื่อสารใด ๆ ที่หันออกสู่ภายนอก

## ตัวอย่าง

**องค์กรขนาดใหญ่** ผู้นำวิศวกรรมของบริษัทซอฟต์แวร์เริ่มอ้างถึงข้อมูลความถี่ commit รายบุคคลอย่างไม่เป็นทางการในการหารือเรื่องเลื่อนตำแหน่ง
โดยไม่มีนโยบายทางการ การตรวจสอบภายในซึ่งเกิดจากโครงการวิเคราะห์การลาออกที่ไม่เกี่ยวกัน
พบว่าวิศวกรที่ทำงานกับระบบที่ซับซ้อนและมีมูลค่าสูงที่สุดของบริษัท ซึ่งต้องใช้เวลาออกแบบอย่างรอบคอบนานก่อนเขียนโค้ดบรรทัดแรก
มีจำนวน commit ต่ำกว่าวิศวกรที่ดูแลระบบที่ง่ายกว่าและพัฒนาแบบค่อยเป็นค่อยไปอย่างเป็นระบบ
และเสียเปรียบอย่างแนบเนียนในบทสนทนาเลื่อนตำแหน่งเพราะเหตุนั้น
ผู้นำออกนโยบายที่ชัดแจ้งและสื่อสารแล้วห้ามอ้างจำนวนกิจกรรมในการหารือเรื่องผลงานและการเลื่อนตำแหน่ง
และย้ายหลักฐานการเลื่อนตำแหน่งไปสู่แนวทางประสิทธิภาพแบบหลายสัญญาณจากหัวข้อ 3.3

**ภาครัฐ** หน่วยงานบริการดิจิทัลที่ถูกกดดันให้แสดงผลิตภาพต่อคณะกรรมการกำกับดูแลของสภา
เดิมเสนอรายงาน commit รวมและจำนวนบรรทัดโค้ดที่เขียนทั้งโครงการวิศวกรรมเป็นหลักฐานของคุณค่าที่ส่งมอบ
ที่ปรึกษาทางเทคนิคภายในคัดค้าน โดยชี้ถูกต้องว่ากรอบนี้เชิญชวนการตรวจสอบผิดแบบ
เพราะสมาชิกคณะกรรมการที่มีความรู้ทางเทคนิคชี้ได้ง่าย ๆ ว่าปริมาณโค้ดดิบไม่ได้บอกว่าโค้ดใช้งานได้หรือสำคัญหรือเปล่า
รายงานฉบับแก้ไขของหน่วยงานใช้ตัวชี้วัดผลลัพธ์แทน (หัวข้อ 5.3)
ได้แก่ ข้อผิดพลาดที่ประชาชนรายงานลดลงและอัตราการทำรายการด้วยตนเองสำเร็จเพิ่มขึ้น
ซึ่งทนต่อการซักถามของคณะกรรมการได้ดีกว่าตัวเลขกิจกรรมมาก

## เหตุผลทางธุรกิจ: แรงจูงใจ ROI และ TCO

ผลตอบแทนของการใช้ตัวชี้วัดกิจกรรมให้ถูก คือใช้ตามบริบทแทนใบคะแนนรายบุคคล ก็คือความเสียหายที่หลีกเลี่ยงได้
องค์กรที่จัดอันดับวิศวกรรายบุคคลด้วยกิจกรรมจะพบพฤติกรรมเล่นแร่แปรธาตุอย่างแน่นอน
การร่วมมือที่ลดลง (วิศวกรปกป้องผลงานที่มองเห็นของตนแทนที่จะช่วยเพื่อนร่วมทีม)
และอคติเชิงระบบต่อกิจกรรมเชิงลึกที่มีแรงส่งสูง ซึ่งมักสร้างคุณค่ามากที่สุดขณะที่สร้างกิจกรรมที่มองเห็นน้อยที่สุด
การย้อนความเสียหายนั้นเมื่อฝังรากในวัฒนธรรมการประเมินผลงานแล้วเป็นเรื่องยากและช้าจริง ๆ

ต้นทุนรวมของการหลีกเลี่ยงกับดักนี้ส่วนใหญ่คือวินัยขององค์กร
นโยบายที่ชัดแจ้งและบังคับใช้อย่างสม่ำเสมอต่อต้านการจัดอันดับกิจกรรมรายบุคคล
และความมุ่งมั่นที่จะลงทุนในการวัดประสิทธิภาพที่ยากกว่าและตรงไปตรงมากว่าตามที่หัวข้อ 3.3 อธิบายแทน
วินัยนั้นมีต้นทุนต่ำกว่าการตัดสินใจเลื่อนตำแหน่งที่ผิดทิศ การร่วมมือที่เสียหาย
และพฤติกรรมเล่นแร่แปรธาตุที่ตัวชี้วัดกิจกรรมรายบุคคลสร้างขึ้นอย่างแน่นอนเมื่อเวลาผ่านไป

## แอนตี้แพตเทิร์นและข้อผิดพลาด

- **จัดอันดับรายบุคคลด้วยจำนวน commit หรือจำนวนบรรทัดโค้ด:** การใช้ผิดที่สร้างความเสียหายมากที่สุดและพบบ่อยที่สุดในประวัติศาสตร์ของหนังสือทั้งเล่ม
- **การแสดงละครกิจกรรม:** งานที่ทำเป็นหลักเพื่อให้มองเห็นแทนที่จะมีคุณค่า
  เป็นการตอบสนองที่คาดเดาได้ทั้งหมดต่อการประเมินตามกิจกรรม
- **ตีความกิจกรรมระดับทีมที่ลดลงโดยแยกเดี่ยว โดยไม่ตรวจมิติอื่นของ SPACE:**
  อาจเข้าใจรูปแบบเชิงบวกจริงว่าเป็นเรื่องน่ากังวล
- **อ้างจำนวนกิจกรรมดิบในการสื่อสารกับภายนอกหรือกับผู้นำ:** เชิญชวนการตรวจสอบผิดแบบและบอกเกี่ยวกับคุณค่าจริงได้น้อย
- **ประเมินต่ำกว่าจริงอย่างเป็นระบบต่องานเชิงลึกที่รอบคอบซึ่งสร้างเหตุการณ์ที่มองเห็นได้น้อย:**
  อคติเชิงโครงสร้างที่ฝังอยู่ในตระกูลตัวชี้วัดนี้ทั้งตระกูล
- **อคติเรื่องกิจกรรมแบบไม่เป็นทางการและไร้นโยบายแทรกเข้าสู่การสนทนาเรื่องเลื่อนตำแหน่งหรือประเมินผล:**
  สร้างความเสียหายได้แม้ไม่มีตัวชี้วัดทางการหนุนหลัง

## แบบจำลองวุฒิภาวะ

- **ระดับ 1 เริ่มต้น (Initiate):** ใช้ตัวชี้วัดกิจกรรมประเมินหรือจัดอันดับรายบุคคล
  ทั้งแบบเป็นทางการหรือไม่เป็นทางการ โดยไม่ตระหนักถึงความเสี่ยง
- **ระดับ 2 พัฒนา (Develop):** มีความตระหนักถึงความเสี่ยงบ้าง
  แต่ไม่มีนโยบายชัดแจ้งป้องกันไม่ให้ข้อมูลกิจกรรมมีอิทธิพลต่อการประเมินหรือการหารือเลื่อนตำแหน่งแบบไม่เป็นทางการ
- **ระดับ 3 สร้างมาตรฐาน (Standardize):** นโยบายที่ชัดแจ้งและสื่อสารทั่วองค์กรห้ามจัดอันดับกิจกรรมรายบุคคล
  และใช้ข้อมูลกิจกรรมเฉพาะในรูปผลรวมตามบริบทระดับทีม
- **ระดับ 4 บริหารจัดการ (Manage):** ตรวจสอบแนวปฏิบัติการประเมินผลงานและเลื่อนตำแหน่งเป็นระยะเพื่อยืนยันว่านโยบายถูกปฏิบัติตามจริง
  และสัญญาณกิจกรรมที่ปรับด้วยคุณภาพแทนที่จำนวนดิบในที่ที่ใช้ข้อมูลกิจกรรมเลย
- **ระดับ 5 ประสาน (Orchestrate):** องค์กรเปลี่ยนวัฒนธรรมการประเมินจากตัวชี้วัดกิจกรรมไปสู่แนวทางประสิทธิภาพแบบหลายสัญญาณของหัวข้อ 3.3
  ได้อย่างพิสูจน์ได้ โดยมีการร่วมมือที่ดีขึ้นอย่างเห็นได้และพฤติกรรมเล่นแร่แปรธาตุที่ลดลงเป็นหลักฐานว่าการเปลี่ยนได้ผล

## ประเด็นเพื่อการอภิปราย

1. เคยมีใครที่นี่รู้สึกว่าถูกประเมิน แม้แบบไม่เป็นทางการ จากกิจกรรมของตนที่ดู "ยุ่ง" แค่ไหนหรือไม่?
2. การแสดงละครกิจกรรมจะหน้าตาอย่างไรในทีมของเราโดยเฉพาะ?
3. เรามีนโยบายที่เป็นลายลักษณ์อักษรและชัดแจ้งต่อต้านการจัดอันดับกิจกรรมรายบุคคลหรือไม่ และมีการปฏิบัติตามจริงหรือเปล่า?
4. งานเงียบที่มีคุณค่าสูงชิ้นใดในทีมของเราที่ตอนนี้สร้างข้อมูลกิจกรรมให้เห็นน้อยที่สุด?
5. เราจะออกแบบหลักฐานการประเมินผลงานใหม่อย่างไรเพื่อตัดจำนวนกิจกรรมออกไปทั้งหมด?

## ข้อสรุปสำคัญ

- กิจกรรมวัด **การเคลื่อนไหว ไม่ใช่คุณค่า** เป็นตระกูลตัวชี้วัดที่ถูกใช้ผิดมากที่สุดในประวัติศาสตร์วิศวกรรมซอฟต์แวร์
- **อย่าจัดอันดับหรือประเมินรายบุคคล** ด้วยจำนวนกิจกรรมดิบ นี่คือกฎที่ยากที่สุดและสำคัญที่สุดของหัวข้อนี้
- ใช้ข้อมูลกิจกรรม **ในรูปผลรวม เป็นบริบท** ให้มิติอื่นของ SPACE ไม่เคยเป็นคำตัดสินเดี่ยว
- จับตา **การแสดงละครกิจกรรม** และ **รูปแบบการเล่นแร่แปรธาตุแบบการแทนที่** (หัวข้อ 1.2) ในตระกูลตัวชี้วัดนี้โดยเฉพาะ
- งานเชิงลึกที่มีคุณค่าสูงมักสร้าง **ข้อมูลกิจกรรมที่มองเห็นน้อยที่สุด** ปกป้องมันจากการถูกประเมินต่ำกว่าจริงอย่างเป็นระบบ
