# 8.2 ภูมิทัศน์เครื่องมือ: สร้างเองหรือซื้อ

## ภาพรวมและแรงจูงใจ

ทุกองค์กรที่นำคำแนะนำของหนังสือเล่มนี้ไปใช้ ในที่สุดต้องเผชิญการตัดสินใจเรื่องโครงสร้างพื้นฐานเชิงปฏิบัติ:
สร้างเครื่องมือด้านตัวชี้วัดขึ้นเองภายในองค์กร ซื้อแพลตฟอร์มวิเคราะห์วิศวกรรมเชิงพาณิชย์
หรือที่พบบ่อยที่สุดในทางปฏิบัติคือผสมกันทั้งสองแบบ
หัวข้อนี้มองการตัดสินใจนั้นด้วยความเข้มงวดเดียวกับที่หัวข้อ 5.5 ใช้กับการลงทุนด้านวิศวกรรมอื่นๆ:
การวิเคราะห์ต้นทุนและประโยชน์อย่างซื่อสัตย์ที่เฉพาะเจาะจงกับขนาดองค์กรของคุณ แหล่งข้อมูลที่มีอยู่
และตัวชี้วัดจากหนังสือเล่มนี้ที่คุณตั้งใจติดตามจริง
แทนที่จะใช้คำตอบสำเร็จรูปที่ใช้เหมือนกันหมดโดยไม่สนบริบท

ตลาดเครื่องมือวิเคราะห์วิศวกรรมเชิงพาณิชย์เติบโตเต็มที่ขึ้นมาก
และหลายแพลตฟอร์มในปัจจุบันมีการติดตั้งเครื่องมือวัดที่แข็งแรงและอัตโนมัติเป็นส่วนใหญ่สำหรับตัวชี้วัด DORA (ส่วนที่ 2)
ข้อมูล pull request และการทบทวน (หัวข้อ 2.9) และมีโครงสร้างพื้นฐานแบบสำรวจประสบการณ์นักพัฒนามากขึ้นเรื่อยๆ (หัวข้อ 3.7)
ความเติบโตนี้ทำให้หลายองค์กรเอนไปทางการซื้ออย่างน้อยก็ชั้นพื้นฐาน
แต่ไม่ได้ลบข้อได้เปรียบที่แท้จริงของการสร้างเองสำหรับความต้องการเฉพาะที่ปรับแต่งเอง
โดยเฉพาะเรื่องเทเลเมทรีผลลัพธ์ที่หัวข้อ 7.4 ชี้ว่าตอนนี้ต้องเป็นศูนย์กลางของโปรแกรมตัวชี้วัด
ซึ่งมักเป็นหมวดการวัดที่มาตรฐานน้อยที่สุดและเฉพาะองค์กรมากที่สุดในหนังสือเล่มนี้

สำหรับทีมขนาดใหญ่ การตัดสินใจนี้ส่งผลต่องบประมาณและกำลังวิศวกรรมอย่างต่อเนื่องจริง
องค์กรขนาดใหญ่มักต้องรวมเครื่องมือด้านตัวชี้วัดข้ามภูมิทัศน์ที่หลากหลายจริงของระบบเก่าและระบบใหม่
ซึ่งกำหนดการคิดเรื่องสร้างเองหรือซื้ออย่างมาก
ส่วนหน่วยงานรัฐมักเผชิญข้อจำกัดด้านการจัดซื้อและข้อกำหนดด้านอธิปไตยของข้อมูลหรือความมั่นคงปลอดภัย
ที่กระทบอย่างมีนัยสำคัญว่าตัวเลือกเชิงพาณิชย์ใดใช้ได้จริง
บางครั้งเอียงการตัดสินใจไปทางสร้างเองหรือไปทางผู้ขายที่ผ่านการตรวจสอบเฉพาะราย
ไม่ว่าการวิเคราะห์ต้นทุนและประโยชน์ล้วนๆ จะชี้ไปทางใด

## หลักการสำคัญ

- **นี่แทบไม่ใช่การตัดสินใจแบบเอาทั้งหมดหรือไม่เอาเลย**
  โปรแกรมตัวชี้วัดที่เติบโตเต็มที่ส่วนใหญ่ผสมเครื่องมือที่ซื้อสำหรับตัวชี้วัดมาตรฐานชัดเจน
  กับเครื่องมือที่สร้างเองสำหรับเทเลเมทรีผลลัพธ์เฉพาะองค์กร
- **ซื้อสำหรับตัวชี้วัดมาตรฐานที่ต้องใช้กันกว้างขวาง สร้างสำหรับตัวชี้วัดที่เฉพาะองค์กรจริงๆ**
  ตัวชี้วัด DORA และการวิเคราะห์ pull request เป็นเขตสินค้าโภคภัณฑ์
  ส่วนความสัมพันธ์กับผลลัพธ์ทางธุรกิจเฉพาะของคุณ (หัวข้อ 5.3) มักไม่ใช่
- **ความเป็นเจ้าของและความสามารถในการย้ายข้อมูลสำคัญพอๆ กับการเปรียบเทียบฟีเจอร์**
  เครื่องมือที่ล็อกข้อมูลตัวชี้วัดของคุณไว้เป็นความเสี่ยงที่ติดตัวยาวนาน ไม่ใช่แค่ความไม่สะดวก
- **ต้นทุนการผนวกรวมมักถูกประเมินต่ำเกินไป** ในการวิเคราะห์สร้างเองหรือซื้อ ทั้งสองทางเลือก
- **ข้อจำกัดด้านการจัดซื้อ ความมั่นคงปลอดภัย และอธิปไตยของข้อมูลอาจชนะการคำนวณต้นทุนและประโยชน์ล้วนๆ**
  โดยเฉพาะสำหรับหน่วยงานรัฐ

## ข้อเสนอแนะ

### ซื้อสำหรับชั้นสินค้าโภคภัณฑ์: DORA การทบทวน และโครงสร้างพื้นฐานแบบสำรวจ

สำหรับตระกูลตัวชี้วัดที่มีเครื่องมือเชิงพาณิชย์ที่เติบโตและหาได้กว้างขวาง
คือการติดตั้งเครื่องมือวัดตัวชี้วัด DORA (ส่วนที่ 2) การวิเคราะห์ pull request และการทบทวนโค้ด (หัวข้อ 2.9)
และแพลตฟอร์มสำรวจประสบการณ์นักพัฒนา (หัวข้อ 3.7)
การซื้อมักเป็นทางเลือกทางเศรษฐศาสตร์ที่ดีกว่าสำหรับองค์กรส่วนใหญ่ที่ต่ำกว่าขนาดระดับหนึ่ง
เพราะการสร้างโครงสร้างพื้นฐานเทียบเท่าซ้ำซ้อนกับแรงวิศวกรรมที่ผู้ขายหลายรายลงทุนไปมากแล้ว
โดยมีความแตกต่างที่แท้จริงจากการสร้างเวอร์ชันของตัวเองได้จำกัด

### สร้างสำหรับเทเลเมทรีผลลัพธ์ที่เฉพาะองค์กรจริงๆ

สำหรับตัวชี้วัดผลลัพธ์ที่หัวข้อ 7.4 ชี้ว่าควรเป็นศูนย์ถ่วงของโปรแกรมตัวชี้วัดของคุณ
ได้แก่ ความสัมพันธ์กับผลลัพธ์ทางธุรกิจ (หัวข้อ 5.3) การรับฟีเจอร์ไปใช้ที่ผูกกับผลิตภัณฑ์เฉพาะของคุณ (หัวข้อ 5.2)
และเศรษฐศาสตร์ต่อหน่วยที่ผูกกับโครงสร้างต้นทุนเฉพาะของคุณ (หัวข้อ 5.4)
เครื่องมือเชิงพาณิชย์มีมาตรฐานน้อยกว่ามาก และมักจับตรรกะทางธุรกิจและแบบจำลองข้อมูลเฉพาะขององค์กรคุณไม่ได้
หากไม่ปรับแต่งอย่างกว้างขวางและแพง ซึ่งอาจลงเอยด้วยต้นทุนสูงกว่าการสร้างขีดความสามารถเทียบเท่าภายในที่ควบคุมผลลัพธ์ได้เต็มที่

### ประเมินความเป็นเจ้าของและความสามารถในการย้ายข้อมูลก่อนผูกพันกับผู้ขาย

ก่อนเซ็นสัญญาเชิงพาณิชย์ ยืนยันว่าคุณส่งออกข้อมูลตัวชี้วัดย้อนหลังทั้งหมดในรูปแบบมาตรฐานที่ใช้งานได้
และเข้าใจว่าข้อมูลและประวัติของมันจะเป็นอย่างไรหากคุณเปลี่ยนผู้ขายหรือยกเลิกบริการ
ความสัมพันธ์กับผู้ขายที่ออกยากเพราะข้อมูลถูก[ล็อกอิน](https://en.wikipedia.org/wiki/Vendor_lock-in)เป็นความเสี่ยงติดตัวขององค์กร ไม่ใช่แค่ความไม่สะดวก
และการประเมินนี้ควรได้รับความจริงจังเท่ากับข้อผูกพันด้านโครงสร้างพื้นฐานหลายปีที่สำคัญอื่นๆ

### ตั้งงบต้นทุนการผนวกรวมตามความเป็นจริงทั้งสองฝั่งของการตัดสินใจ

ไม่ว่าจะสร้างหรือซื้อ ต้นทุนการผนวกรวม คือการเชื่อมเครื่องมือเข้ากับระบบควบคุมเวอร์ชัน CI/CD
การติดตามเหตุการณ์ขัดข้อง และระบบธุรกิจจริงของคุณ มักถูกประเมินต่ำเกินไปในการวางแผนเริ่มแรกของทั้งสองทาง
ตั้งงบสำหรับงานผนวกรวมนี้อย่างชัดเจนเป็นรายการสำคัญแยกต่างหากในการวิเคราะห์สร้างเองหรือซื้อ
แทนที่จะสมมติว่าเครื่องมือเชิงพาณิชย์ใช้ได้ทันทีโดยตั้งค่าน้อยนิด
หรือว่าต้นทุนการผนวกรวมของโซลูชันที่สร้างเองเป็นส่วนเพิ่มเล็กน้อยจากต้นทุนการพัฒนา

### คิดถึงข้อจำกัดด้านการจัดซื้อ ความมั่นคงปลอดภัย และอธิปไตยอย่างชัดเจนและตั้งแต่เนิ่นๆ

สำหรับหน่วยงานรัฐและองค์กรที่อยู่ภายใต้กฎระเบียบ ข้อกำหนดด้านอธิปไตยของข้อมูล ความต้องการใบรับรองด้านความมั่นคงปลอดภัย
และกระบวนการจัดซื้ออาจจำกัดหรือตัดตัวเลือกเชิงพาณิชย์บางรายออกไปอย่างมีนัยสำคัญ ไม่ว่าฟีเจอร์จะดีเพียงใด
บางครั้งเอียงการตัดสินใจไปทางสร้างเองหรือไปทางผู้ขายที่ผ่านการตรวจสอบเฉพาะกลุ่มเล็ก
ระบุข้อจำกัดเหล่านี้อย่างชัดเจนและตั้งแต่ต้นของกระบวนการประเมิน
แทนที่จะมาค้นพบเมื่อทุ่มแรงประเมินไปกับตัวเลือกหนึ่งมากแล้วและพบว่าใช้ไม่ได้ด้วยเหตุผลที่ไม่เกี่ยวกับความสามารถจริงของมัน

## ข้อแลกเปลี่ยน: ข้อดีและข้อเสีย

| แนวทาง | ข้อดี | ข้อเสีย |

| สร้างเครื่องมือภายใน | ปรับแต่งได้เต็มที่ เป็นเจ้าของและควบคุมข้อมูลได้เต็มที่ | ต้องลงทุนด้านวิศวกรรมต่อเนื่องและมาก ซ้ำซ้อนกับแรงงานสำหรับตัวชี้วัดสินค้าโภคภัณฑ์ |
| ผสม: ซื้อชั้นสินค้าโภคภัณฑ์ สร้างชั้นผลลัพธ์ | สมดุลระหว่างประสิทธิภาพด้านต้นทุนกับการปรับแต่งจริงในจุดที่สำคัญที่สุด | ต้องทำงานผนวกรวมเพื่อเชื่อมส่วนที่ซื้อกับส่วนที่สร้างให้สอดคล้องกัน |
| ซื้อทุกอย่างรวมถึงเทเลเมทรีผลลัพธ์ ผ่านการปรับแต่งของผู้ขายอย่างกว้างขวาง | ความสัมพันธ์กับผู้ขายรายเดียว อาจจัดซื้อง่ายกว่า | อาจแพงเท่าการสร้างเอง โดยควบคุมผลลัพธ์สุดท้ายได้น้อยกว่า |

ความตึงเครียดหลักคือ **ความต้องการปรับแต่งเทียบกับต้นทุนการพัฒนา**
ตัวชี้วัดที่ได้ประโยชน์จากการปรับแต่งมากที่สุด คือเทเลเมทรีผลลัพธ์ที่ผูกกับธุรกิจของคุณโดยเฉพาะ ก็แพงที่สุดที่จะสร้างให้ดีด้วย
ส่วนตัวชี้วัดที่ซื้อถูกที่สุด คือ DORA และการวิเคราะห์การทบทวน ก็เป็นตัวที่การปรับแต่งสำคัญน้อยที่สุด
แก้ความตึงเครียดนี้ด้วยการจับคู่การตัดสินใจกับรูปแบบนี้โดยตรง:
ซื้อในจุดที่มาตรฐานรับใช้คุณได้ดี สร้างในจุดที่บริบทเฉพาะของคุณต้องการจริงๆ
และตั้งงบต้นทุนการผนวกรวมตามความเป็นจริงทั้งสองฝั่งของการแบ่งนั้น

## คำถามเพื่อหารือกับทีมของคุณ

1. **สำหรับแต่ละตระกูลตัวชี้วัดที่หนังสือเล่มนี้กล่าวถึง เราจะได้ประโยชน์จากการปรับแต่งจริงหรือไม่ หรือเครื่องมือเชิงพาณิชย์มาตรฐานรับใช้เราได้พอๆ กัน?**
   ไล่ดูส่วนที่ 2 ถึง 6 อย่างชัดเจน และจัดแต่ละตระกูลตัวชี้วัดลงคอลัมน์ซื้อหรือสร้างตามการทดสอบเฉพาะนี้

2. **เราได้ประเมินตัวเลือกการส่งออกและการย้ายข้อมูลของผู้ขายปัจจุบันหรือที่กำลังพิจารณาหรือไม่ หรือเราแค่สมมติว่าออกได้ง่ายถ้าจำเป็น?**
   ตรวจสอบโดยตรงแทนการสมมติ การล็อกอินของข้อมูลมักถูกค้นพบเมื่อองค์กรลองเปลี่ยนผู้ขายจริงเท่านั้น

3. **การวิเคราะห์สร้างเองหรือซื้อครั้งแรกของเราคิดต้นทุนการผนวกรวมตามความเป็นจริงหรือไม่ หรือเน้นแต่ค่าลิขสิทธิ์เทียบกับชั่วโมงพัฒนา?**
   ย้อนดูการตัดสินใจเรื่องเครื่องมือล่าสุดและตรวจว่าต้นทุนการผนวกรวมถูกประเมินจริงหรือประเมินต่ำไปมาก

4. **เราเผชิญข้อจำกัดด้านการจัดซื้อ ความมั่นคงปลอดภัย หรืออธิปไตยของข้อมูลที่จะตัดตัวเลือกเชิงพาณิชย์บางรายออกไปไม่ว่าฟีเจอร์จะดีแค่ไหนหรือไม่?**
   ระบุข้อจำกัดเหล่านี้อย่างชัดเจนก่อน ไม่ใช่หลังจากทุ่มแรงประเมินกับตัวเลือกที่อาจใช้ไม่ได้

5. **ภูมิทัศน์เครื่องมือปัจจุบันของเราเป็นแบบผสมที่ตั้งใจ จับคู่การสร้างและการซื้อในจุดที่เหมาะ หรือสะสมมาจากการตัดสินใจเฉพาะกิจที่ดูสมเหตุสมผลทีละครั้งตามกาลเวลา?**
   ซื่อสัตย์ว่ารูปแบบใดอธิบายสถานการณ์ปัจจุบันของคุณจริงๆ

6. **ถ้าต้องเปลี่ยนผู้ขายเครื่องมือตัวชี้วัดวันนี้ จะต้องเสียแรงและความเสี่ยงเท่าไร?**
   คำถามที่เป็นรูปธรรมนี้ทดสอบความเสี่ยงล็อกอินของข้อมูลที่คุณเผชิญจริงในปัจจุบัน
   เกินกว่าที่เงื่อนไขในสัญญาของผู้ขายสัญญาไว้ในนาม

## มุมมองตามภาคส่วน

**สตาร์ทอัป** ซื้อเครื่องมือสินค้าโภคภัณฑ์เป็นค่าเริ่มต้นในขนาดนี้
การสร้างโครงสร้างพื้นฐานตัวชี้วัดแบบกำหนดเองแทบไม่ใช่การใช้กำลังวิศวกรรมช่วงต้นที่มีจำกัดอย่างคุ้มค่า
เมื่อมีตัวเลือกเชิงพาณิชย์ที่เติบโตและราคาไม่แพงสำหรับตัวชี้วัด DORA และการทบทวนโดยเฉพาะ
สงวนแรงสร้างไว้สำหรับตัวชี้วัดผลลัพธ์เดียว (หัวข้อ 5.3) ที่สะท้อนคุณค่าหลักของผลิตภัณฑ์คุณโดยตรงที่สุด

**ธุรกิจขนาดเล็ก** ตัวเลือกเครื่องมือเชิงพาณิชย์ส่วนใหญ่ย่อขนาดลงได้ดีพอสมควรและตั้งราคาให้องค์กรเล็กเข้าถึงได้
การซื้อชั้นสินค้าโภคภัณฑ์เกือบทุกครั้งเป็นทางเลือกที่ถูก
และการสร้างอะไรแบบกำหนดเองแทบไม่คุ้มจนกว่าองค์กรจะเติบโตมากและมีความต้องการเฉพาะจริง

**องค์กรขนาดใหญ่** แนวทางผสมที่หัวข้อนี้แนะนำคุ้มค่ากับความซับซ้อนตรงนี้:
ซื้อชั้นสินค้าโภคภัณฑ์ในระดับใหญ่ (มักมีอำนาจต่อรองเงื่อนไขที่เป็นคุณได้จริง)
และลงทุนสร้างชั้นเทเลเมทรีผลลัพธ์เฉพาะองค์กรอย่างตั้งใจ
เพราะตรรกะทางธุรกิจและความซับซ้อนของแบบจำลองข้อมูลของคุณในขนาดนี้มักเกินกว่าที่เครื่องมือเชิงพาณิชย์ทั่วไปรองรับได้
หากไม่ปรับแต่งอย่างกว้างขวางและแพง

**หน่วยงานรัฐ** กระบวนการจัดซื้อ ข้อกำหนดใบรับรองด้านความมั่นคงปลอดภัย และข้อจำกัดด้านอธิปไตยของข้อมูล
มักครอบงำการตัดสินใจนี้มากกว่าที่การเปรียบเทียบฟีเจอร์หรือต้นทุนล้วนๆ ชี้
ดึงผู้มีส่วนได้ส่วนเสียด้านจัดซื้อและความมั่นคงปลอดภัยเข้ามาตั้งแต่ต้นของการประเมิน
และเตรียมใจว่าตัวเลือกสร้างเองอาจน่าสนใจกว่าบริบทภาคเอกชนที่เทียบเคียงกันได้จริง
เพราะข้อจำกัดเหล่านี้โดยเฉพาะ ไม่ใช่เพราะการสร้างเองดีกว่าโดยธรรมชาติ

## ตัวอย่าง

**องค์กรขนาดใหญ่** บริษัทซอฟต์แวร์แห่งหนึ่งเริ่มด้วยการพยายามสร้างแพลตฟอร์มตัวชี้วัดแบบกำหนดเองเต็มรูปแบบ
ครอบคลุมทุกตระกูลตัวชี้วัดตั้งแต่ส่วนที่ 2 ถึงส่วนที่ 6 เป็นความพยายามหลายปีที่ใช้กำลังวิศวกรรมมาก
และยังตามหลังข้อเสนอเชิงพาณิชย์ที่เติบโตแล้วสำหรับตัวชี้วัด DORA และการทบทวนมาตรฐานโดยเฉพาะ
กลยุทธ์ที่แก้ไขใหม่เลือกแพลตฟอร์มเชิงพาณิชย์สำหรับตัวชี้วัดสินค้าโภคภัณฑ์เหล่านี้
ปล่อยให้ทีมแพลตฟอร์มภายในโฟกัสเฉพาะการสร้างเทเลเมทรีความสัมพันธ์กับผลลัพธ์ทางธุรกิจและเศรษฐศาสตร์ต่อหน่วย (หัวข้อ 5.3, 5.4)
ที่เฉพาะกับแบบจำลองธุรกิจของบริษัทจริงๆ ซึ่งไม่มีเครื่องมือเชิงพาณิชย์ใดให้ได้ทันที
แนวทางผสมนี้ส่งมอบโปรแกรมตัวชี้วัดที่ครบถ้วนกว่าและมีประโยชน์จริงกว่าภายในหนึ่งปี
เทียบกับกลยุทธ์สร้างเองทั้งหมดที่ทำได้หลังสองปี

**หน่วยงานรัฐ** การประเมินแพลตฟอร์มวิเคราะห์วิศวกรรมเชิงพาณิชย์ครั้งแรกของหน่วยงานรัฐบาลกลางแห่งหนึ่ง
พบว่าไม่มีผู้ขายรายใดตอบสนองข้อกำหนดด้านอธิปไตยของข้อมูลของหน่วยงานได้
ซึ่งกำหนดให้ข้อมูลตัวชี้วัดวิศวกรรมทั้งหมดต้องอยู่ในศูนย์ข้อมูลของรัฐที่ผ่านการรับรองโดยเฉพาะ
แทนที่จะทิ้งตัวเลือกซื้อไปทั้งหมด หน่วยงานระบุกลุ่มย่อยเล็กๆ ของผู้ขายที่มีตัวเลือกติดตั้งบนคลาวด์อธิปไตยที่รัฐรับรอง
โดยมีส่วนเพิ่มราคาเล็กน้อยจากราคาเชิงพาณิชย์มาตรฐาน และติดตั้งโปรแกรมแบบผสมได้สำเร็จ:
ซื้อเครื่องมือสำหรับชั้นตัวชี้วัดสินค้าโภคภัณฑ์ภายในขอบเขตอธิปไตยที่กำหนด
และสร้างเครื่องมือภายในสำหรับความต้องการเทเลเมทรีผลลัพธ์ต่อประชาชนเฉพาะของหน่วยงาน
ซึ่งไม่มีผู้ขายเชิงพาณิชย์รายใดตอบโจทย์ ไม่ว่าจะพิจารณาเรื่องอธิปไตยหรือไม่

## เหตุผลทางธุรกิจ: แรงจูงใจ ROI และ TCO

ผลตอบแทนของกลยุทธ์สร้างเองหรือซื้อแบบผสมที่ตั้งใจคือการหลีกเลี่ยงความล้มเหลวทั้งสองแบบที่ตัวอย่างของหัวข้อนี้แสดง:
การลงทุนด้านวิศวกรรมหลายปีที่สูญเปล่าไปกับการสร้างขีดความสามารถสินค้าโภคภัณฑ์ที่มีอยู่ในตลาดในราคาถูกแล้ว
และความหงุดหงิดกับต้นทุนการปรับแต่งในที่สุดจากการยัดความต้องการเฉพาะองค์กรจริงๆ เข้าไปในเครื่องมือเชิงพาณิชย์ที่ไม่เหมาะ
ตัวอย่างองค์กรขนาดใหญ่ข้างต้นแสดงเรื่องนี้เป็นรูปธรรม:
แนวทางผสมส่งมอบคุณค่าจริงมากกว่าในหนึ่งปีเทียบกับกลยุทธ์สร้างเองทั้งหมดในสองปี

ต้นทุนการเป็นเจ้าของรวมของทั้งสองทางรวมต้นทุนการผนวกรวม ซึ่งมักประเมินต่ำไป
และสำหรับเครื่องมือที่ซื้อโดยเฉพาะ รวมต้นทุนความเสี่ยงต่อเนื่องของการล็อกอินผู้ขายที่อาจเกิดขึ้น
เว้นแต่จะยืนยันและคุ้มครองความสามารถในการย้ายข้อมูลไว้ในสัญญาตั้งแต่แรก
การตั้งงบสำหรับทั้งสองอย่างนี้ตามความเป็นจริง แทนที่จะโฟกัสแคบๆ ที่ค่าลิขสิทธิ์หรือชั่วโมงพัฒนาอย่างเดียว
ให้ภาพต้นทุนรวมที่แม่นยำกว่ามากสำหรับทั้งสองตัวเลือก

## แอนตี้แพตเทิร์นและข้อผิดพลาด

- **สร้างเครื่องมือแบบกำหนดเองสำหรับตัวชี้วัดสินค้าโภคภัณฑ์ที่เป็นมาตรฐานชัดเจน:**
  ซ้ำซ้อนกับแรงวิศวกรรมที่ผู้ขายหลายรายลงทุนไปมากแล้ว
- **ซื้อเครื่องมือเชิงพาณิชย์สำหรับเทเลเมทรีผลลัพธ์เฉพาะองค์กรจริงๆ โดยไม่ตรวจความเหมาะสมก่อน:**
  เสี่ยงต่อการปรับแต่งที่แพงและไม่เหมาะ หรือความต้องการที่ไม่ได้รับการตอบสนอง
- **ไม่ประเมินการส่งออกและความสามารถในการย้ายข้อมูลก่อนผูกพันกับผู้ขาย:**
  เสี่ยงต่อการล็อกอินที่แพงและติดตัวยาวนาน ซึ่งค้นพบเมื่อพยายามออกเท่านั้น
- **ประเมินต้นทุนการผนวกรวมต่ำเกินไปทั้งสองฝั่งของการตัดสินใจ:**
  ให้การเปรียบเทียบต้นทุนรวมที่ไม่แม่นยำและกรอบเวลาที่ไม่สมจริง
- **ละเลยข้อจำกัดด้านการจัดซื้อ ความมั่นคงปลอดภัย หรืออธิปไตยจนถึงช่วงท้ายของการประเมิน:**
  เสียแรงประเมินไปกับตัวเลือกที่ใช้ไม่ได้ด้วยเหตุผลที่ไม่เกี่ยวกับความสามารถ
- **มองว่านี่เป็นการตัดสินใจครั้งเดียวแบบเอาทั้งหมดหรือไม่เอาเลย:**
  พลาดแนวทางผสมที่ตรงกับความต้องการจริงที่หลากหลายขององค์กรส่วนใหญ่ที่สุด

## แบบจำลองวุฒิภาวะ

- **ระดับ 1 เริ่มต้น (Initiate):** การตัดสินใจเรื่องเครื่องมือทำแบบเฉพาะกิจ
  ไม่มีการวิเคราะห์สร้างเองหรือซื้ออย่างตั้งใจ หรือการพิจารณาความสามารถในการย้ายข้อมูล
- **ระดับ 2 พัฒนา (Develop):** มีการวิเคราะห์อยู่บ้าง แต่ต้นทุนการผนวกรวมถูกประเมินต่ำเป็นประจำ
  และไม่ได้พิจารณาแนวทางผสมอย่างตั้งใจ
- **ระดับ 3 สร้างมาตรฐาน (Standardize):** กลยุทธ์สร้างเองหรือซื้อแบบผสมที่ตั้งใจ
  จับคู่ตัวชี้วัดสินค้าโภคภัณฑ์กับเครื่องมือที่ซื้อ และเทเลเมทรีผลลัพธ์เฉพาะองค์กรกับเครื่องมือที่สร้าง อย่างสม่ำเสมอ
- **ระดับ 4 บริหารจัดการ (Manage):** ความสามารถในการย้ายข้อมูลได้รับการยืนยันและคุ้มครองไว้ในสัญญาสำหรับเครื่องมือที่ซื้อทั้งหมด
  และข้อจำกัดด้านการจัดซื้อ ความมั่นคงปลอดภัย และอธิปไตยได้รับการพิจารณาอย่างชัดเจนและตั้งแต่เนิ่นๆ
- **ระดับ 5 ประสาน (Orchestrate):** ภูมิทัศน์เครื่องมือขององค์กรสะท้อนกลยุทธ์ผสมที่เติบโตและตั้งใจ
  ทบทวนเป็นประจำเมื่อข้อเสนอเชิงพาณิชย์และความต้องการขององค์กรเปลี่ยนไป
  พร้อมคุณค่าที่พิสูจน์ได้จากทั้งส่วนที่ซื้อและส่วนที่สร้าง

## ประเด็นเพื่อการอภิปราย

1. ตัวชี้วัดปัจจุบันตัวใดของเราจะได้ประโยชน์มากที่สุดจากการปรับแต่งที่เรายังไม่ได้รับ?
2. เรายืนยันแล้วหรือยังว่าส่งออกข้อมูลตัวชี้วัดย้อนหลังทั้งหมดได้ถ้าจำเป็นต้องเปลี่ยนผู้ขาย?
3. การตัดสินใจเรื่องเครื่องมือครั้งล่าสุดของเราคิดต้นทุนการผนวกรวมตามความเป็นจริงหรือไม่?
4. ข้อจำกัดด้านการจัดซื้อ ความมั่นคงปลอดภัย หรืออธิปไตยข้อใดที่เราอาจประเมินต่ำไป?
5. กลยุทธ์ผสมที่ตั้งใจสำหรับชุดตัวชี้วัดเฉพาะของเราจะเป็นอย่างไร?

- แทบไม่ใช่การเลือกแบบเอาทั้งหมดหรือไม่เอาเลย
  โปรแกรมที่เติบโตเต็มที่ส่วนใหญ่ **ผสมเครื่องมือที่ซื้อสำหรับตัวชี้วัดสินค้าโภคภัณฑ์
  กับเครื่องมือที่สร้างสำหรับเทเลเมทรีผลลัพธ์เฉพาะองค์กร**
- **ซื้อสำหรับตัวชี้วัดมาตรฐาน** (DORA การวิเคราะห์การทบทวน โครงสร้างพื้นฐานแบบสำรวจ)
  **สร้างสำหรับการวัดผลลัพธ์ที่เฉพาะองค์กรจริงๆ**
- ประเมิน**ความเป็นเจ้าของและความสามารถในการย้ายข้อมูล**ก่อนผูกพันกับผู้ขาย
  การล็อกอินเป็นความเสี่ยงติดตัวยาวนาน ไม่ใช่แค่ความไม่สะดวก
- **ตั้งงบต้นทุนการผนวกรวมตามความเป็นจริง**ทั้งสองฝั่งของการตัดสินใจ มักถูกประเมินต่ำไป
- **ข้อจำกัดด้านการจัดซื้อ ความมั่นคงปลอดภัย และอธิปไตย**
  อาจชนะการคำนวณต้นทุนและประโยชน์ล้วนๆ โดยเฉพาะสำหรับหน่วยงานรัฐ
