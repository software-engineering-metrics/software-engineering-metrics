# กฎสไตล์ (ใช้ร่วมกัน บังคับได้)

สไตล์การเขียนในที่เดียว รายการที่มีเครื่องหมาย "(test)" ถูกบังคับโดย
`tests/validate.py` การละเมิดจะทำให้ build ไม่ผ่าน ฉบับบรรยายเต็มคือ
`spec/conventions.md` ที่ราก repository

## กฎเด็ดขาด

- **ห้ามใช้เส้นประยาว** ห้ามใช้อักขระเส้นประยาว (U+2014) ให้ใช้เครื่องหมายจุลภาค มหัพภาคคู่ วงเล็บ หรือ
  แยกเป็นสองประโยค เส้นประสั้น "–" ใช้ได้เฉพาะในช่วงตัวเลข เช่น
  `1–9` หรือ `2.1–2.8` (test)
- **ห้ามใช้สำนวนสำเร็จรูป** ห้ามใช้ "not only ... but also", "but also" หรือ
  "load-bearing" หลีกเลี่ยง "It's important to note", "In today's fast-paced world",
  "It's crucial to consider", "It appears that", "One could argue" และสูตร
  "it's not just X, it's Y" (test สำหรับสามข้อแรก)
- **นิยามศัพท์เมื่อใช้ครั้งแรก** ขยายตัวย่อและนิยามศัพท์เฉพาะในครั้งแรกที่แต่ละหัวข้อใช้
  เช่น "mean time to recovery (MTTR)"
- **ลิงก์แนวคิดสำคัญไปยัง Wikipedia** เมื่อกล่าวถึงครั้งแรก หัวข้อละหนึ่งครั้ง เฉพาะในเนื้อความ
  รูปแบบ: `[term](https://en.wikipedia.org/wiki/Article_Title)` ห้ามใช้ในหัวเรื่อง ตาราง โค้ด
  หรือส่วนอ้างอิง (รูปแบบลิงก์ถูกทดสอบ)
- **อ้างอิงของจริงเท่านั้น** ผู้เขียนและชื่อของผลงานจริง ห้ามแต่งชื่อ ผู้เขียน หรือ URL
- **ระบุ gaming vector** หัวข้อตระกูลตัวชี้วัดต้องระบุว่าตัวชี้วัดถูกเล่นแร่แปรธาตุอย่างไร
  และ guardrail แบบไหนจะจับได้ (หัวข้อ 1.2)

## น้ำเสียง

- อบอุ่น ตรงไปตรงมา ให้กำลังใจ เรียกผู้อ่านว่า "คุณ" ประโยคสั้น คำเรียบง่าย นำด้วยประเด็นสำคัญ
- มีจุดยืนและเป็นประโยชน์ ไม่ฝักใฝ่ผู้ขาย เอ่ยชื่อผลิตภัณฑ์เฉพาะเมื่อเป็นตัวอย่างข้อเท็จจริง

## โครงสร้าง (test)

- หัวข้อเนื้อหาใช้ลำดับส่วนตามที่กำหนดใน
  [`เทมเพลตหัวข้อ.md`](chapter-template.md) เป๊ะ
- หัวเรื่องแรกคือ `# N.M Title` (เลขหัวข้อทศนิยม) และต้องตรงกับคำนำหน้า `PP-CC` ที่เติมศูนย์ของชื่อไฟล์
- เลขในแต่ละส่วนต้องต่อเนื่องและเริ่มที่ N.0
