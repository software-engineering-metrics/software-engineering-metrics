# 9.2 คำจำกัดความตัวชี้วัดและสูตรอ้างอิง

สูตรทุกสูตรจากหนังสือ รวบรวมไว้ในที่เดียว แต่ละรายการระบุหัวข้อที่อภิปรายอย่างครบถ้วน
รวมทั้งความเสี่ยงต่อการถูกเล่นแร่แปรธาตุตัวเลขและ guardrail
ใช้ภาคผนวกนี้เป็นที่เปิดดูอย่างรวดเร็ว ไม่ใช่ตัวแทนของหัวข้อนั้นเอง

## ตัวชี้วัด flow (ส่วนที่ 2)

| ตัวชี้วัด | สูตร | หัวข้อ |
| --- | --- | --- |
| Flow velocity | จำนวน flow item ที่เสร็จต่อหน่วยเวลา | 2.3 |
| Flow distribution | (จำนวนรายการที่เสร็จของ flow item หนึ่งประเภท) / (จำนวนรายการที่เสร็จทั้งหมด) x 100% | 2.3 |
| Flow time | เวลาตั้งแต่ flow item เข้าสู่สายธารคุณค่าจนถึงการส่งมอบ | 2.4 |
| Flow load | จำนวน flow item ที่กำลังทำอยู่หรือรออยู่ในสายธารคุณค่า | 2.4 |
| Little's law | Flow load (งานระหว่างทำ) = อัตราการมาถึง x Flow time (cycle time) | 2.4, 2.7 |
| Flow efficiency | เวลาทำงานจริง / เวลาที่ผ่านไปทั้งหมด x 100% | 2.5 |
| Cycle time | ผลรวมระยะเวลาของแต่ละขั้น: เขียนโค้ด + รอรับงาน + รีวิว + ทดสอบ + deploy | 2.6 |
| Utilization | อัตราการมาถึง / อัตราการให้บริการ | 2.7 |
| Percent complete and accurate (%C/A) | (หน่วยที่ใช้ต่อปลายน้ำได้โดยไม่ต้องแก้ไขซ้ำ) / (หน่วยทั้งหมด) x 100% | 2.8 |
| Rolled throughput yield | %C/A ของขั้นที่ 1 x %C/A ของขั้นที่ 2 x ... x %C/A ของขั้นที่ N | 2.8 |
| Takt time | เวลาทำงานที่มี / ความต้องการของลูกค้าในช่วงเวลานั้น | 2.8 |
| Time to first review | เวลาตั้งแต่เปิด pull request จนถึงที่ผู้รีวิวตอบกลับอย่างมีสาระครั้งแรก | 2.9 |
| Deployment frequency | จำนวนการ deploy ขึ้น production ที่สำเร็จต่อหน่วยเวลา | 2.10 |
| Lead time for changes | เวลาตั้งแต่คอมมิตแรกจนถึงการ deploy ขึ้น production สำเร็จ (รายงานค่ามัธยฐานและเปอร์เซ็นไทล์ที่ 90) | 2.10 |
| Change failure rate | (การ deploy ที่ทำให้เกิดความล้มเหลว) / (การ deploy ทั้งหมด) x 100% | 2.10 |
| Failed deployment recovery time | เวลาตั้งแต่ตรวจพบความล้มเหลวจนถึงการคืนบริการอย่างแท้จริง | 2.10 |

## ประสบการณ์นักพัฒนา (ส่วนที่ 3)

| ตัวชี้วัด | สูตร | หัวข้อ |
| --- | --- | --- |
| Focus time | จำนวนและระยะเวลาของช่วงเวลาที่ไม่ถูกขัดจังหวะตั้งแต่สองชั่วโมงขึ้นไปต่อสัปดาห์ จากข้อมูลปฏิทิน | 3.6 |
| Response rate | (แบบสำรวจที่ได้รับคำตอบ) / (แบบสำรวจที่ส่งคำเชิญ) x 100% | 3.7 |

## โค้ดและคุณภาพ (ส่วนที่ 4)

| ตัวชี้วัด | สูตร | หัวข้อ |
| --- | --- | --- |
| Cyclomatic complexity | เส้นทางอิสระผ่านการควบคุมการไหล (edges − nodes + 2 ตาม McCabe) | 4.1 |
| Test coverage | (บรรทัด/สาขาที่ถูกรันโดยการทดสอบ) / (บรรทัด/สาขาทั้งหมด) x 100% | 4.2 |
| Mutation kill rate | (มิวแทนต์ที่ชุดทดสอบฆ่าได้) / (มิวแทนต์ที่ใส่เข้าไปทั้งหมด) x 100% | 4.2 |
| Code churn | บรรทัดที่เพิ่ม + แก้ไข + ลบ ต่อไฟล์ในช่วงเวลาหนึ่ง | 4.3 |
| Hotspot score | Churn x Complexity จัดอันดับต่อไฟล์ | 4.3 |
| Debt carrying cost | ต้นทุนต่อเนื่องโดยประมาณของการไม่แก้รายการหนึ่ง (งานที่เกี่ยวข้องช้าลง ความเสี่ยงข้อบกพร่องสูงขึ้น) | 4.5 |

## ผลิตภัณฑ์และธุรกิจ (ส่วนที่ 5)

| ตัวชี้วัด | สูตร | หัวข้อ |
| --- | --- | --- |
| Escaped defect rate | (ข้อบกพร่องที่หลุดรอดถ่วงน้ำหนักตามความรุนแรง) / (หน่วยการส่งมอบหรือเวลา) | 5.1 |
| Initial adoption | (ผู้ใช้ที่ลองใช้ฟีเจอร์อย่างน้อยหนึ่งครั้ง) / (กลุ่มเป้าหมาย) x 100% | 5.2 |
| Retained adoption | (ผู้ใช้ที่ยังใช้ฟีเจอร์หลังผ่านไป N สัปดาห์) / (ผู้ใช้ที่ลองใช้ในตอนแรก) x 100% | 5.2 |
| Unit cost | ต้นทุนรวม (บุคลากร + โครงสร้างพื้นฐาน + เครื่องมือ) / หน่วยที่มีความหมาย (ลูกค้า ธุรกรรม) | 5.4 |
| ROI | (ประโยชน์รวม − ต้นทุนรวมของการเป็นเจ้าของ) / ต้นทุนรวมของการเป็นเจ้าของ นำเสนอเป็นช่วง | 5.5 |

## ความน่าเชื่อถือ การดำเนินงาน และความมั่นคงปลอดภัย (ส่วนที่ 6)

| ตัวชี้วัด | สูตร | หัวข้อ |
| --- | --- | --- |
| Error budget | (1 − เป้าหมาย SLO) x ช่วงเวลา (เช่น 0.1% ของ 30 วัน ≈ 43 นาที) | 6.1 |
| Error budget burn rate | Error budget ที่ใช้ไป / Error budget ที่จัดสรรไว้ ในช่วงเวลาหนึ่ง | 6.1 |
| MTTD | เวลาตั้งแต่เหตุการณ์เริ่มจนถึงตรวจพบ | 6.2 |
| MTTA | เวลาตั้งแต่แจ้งเหตุการณ์จนถึงรับทราบ | 6.2 |
| MTTR (เหตุการณ์) | เวลาตั้งแต่รับทราบจนถึงการคืนบริการอย่างแท้จริง | 6.2 |
| On-call page distribution | จำนวน page ที่แต่ละคนได้รับ ในช่วงเวลาแบบเลื่อน (ไม่ใช่ค่าเฉลี่ยของทีม) | 6.3 |
| Vulnerability time-to-remediate | เวลาตั้งแต่พบช่องโหว่จนถึงการแก้ไขอย่างแท้จริง ติดตามตามระดับความรุนแรง | 6.4 |

## หมายเหตุการใช้สูตรเหล่านี้

- **จับคู่สูตรด้านความเร็วหรือผลผลิตกับ guardrail ของมันเสมอ** (หัวข้อ
  1.2): change failure rate คู่กับ deployment frequency และ lead time;
  escaped defect rate คู่กับความเร็วในการส่งมอบ; error budget burn คู่กับ
  กิจกรรมการ deploy
- **ใช้ค่ามัธยฐานและเปอร์เซ็นไทล์ ไม่ใช่ค่าเฉลี่ย กับสูตรที่เกี่ยวกับเวลา**
  (หัวข้อ 1.6) เว้นแต่สูตรนั้นระบุให้ใช้ค่าเฉลี่ยอย่างชัดเจน
- **ทุกสูตรต้องมีระบบแหล่งข้อมูลและวิธีเก็บข้อมูลที่บันทึกไว้**
  (หัวข้อ 1.5) ควบคู่กับนิยามทางคณิตศาสตร์ สองทีมที่คำนวณสูตรเดียวกัน
  จากแหล่งต่างกันจะไม่ได้ตัวเลขที่เทียบกันได้
- **การถ่วงน้ำหนักตามความรุนแรงไม่ได้แสดงไว้ชัดเจนในทุกสูตรข้างต้น** แต่
  ใช้ทุกที่ที่มีคำว่า "ถ่วงน้ำหนักตามความรุนแรง" ดูหัวข้อที่เกี่ยวข้องเพื่อ
  ดูโครงร่างการจัดประเภททั้งหมด
