# 9.3 รายการตรวจสอบ

รายการตรวจสอบฉบับอ้างอิงด่วนที่พร้อมใช้ คัดลอกไปไว้ในกระบวนการของคุณแล้วปรับให้เหมาะ
จุดประสงค์คือความครอบคลุม ไม่ใช่ถ้อยคำที่ตรงเป๊ะ

## รายการตรวจสอบการทบทวนตัวชี้วัดใหม่ (ก่อนเพิ่มตัวชี้วัดใดลงแดชบอร์ด)

- [ ] ตัวชี้วัดมีการตัดสินใจที่ระบุชื่อได้ซึ่งมันช่วยให้ข้อมูล (หัวข้อ 1.1)
- [ ] ตัวชี้วัดถูกจัดประเภทเป็นเชิงวินิจฉัยหรือเชิงประเมินผล เป็นลายลักษณ์อักษร
      (หัวข้อ 1.1)
- [ ] หากมีแรงจูงใจ ได้กำหนดตัวชี้วัด guardrail ไว้พร้อมกัน
      (หัวข้อ 1.2)
- [ ] ได้ระบุ gaming vector แล้ว: ทีมที่มีเหตุผลจะทำให้ตัวเลขนี้ดูดี
      โดยไม่ทำให้ผลลัพธ์จริงดีขึ้นได้อย่างไร (หัวข้อ 1.2)
- [ ] ตัวชี้วัดถูกจัดประเภทเป็น input, output หรือ outcome (หัวข้อ 1.3)
- [ ] ตัวชี้วัดมีเจ้าของที่ระบุชื่อ และมีระบบแหล่งข้อมูลกับวิธีเก็บข้อมูลที่บันทึกไว้
      (หัวข้อ 1.4, 1.5)
- [ ] ตัวชี้วัดจะใช้ค่ามัธยฐานหรือเปอร์เซ็นไทล์ ไม่ใช่ค่าเฉลี่ย หากข้อมูลเบื้องหลังเบ้
      (หัวข้อ 1.6)
- [ ] ตัวชี้วัดไม่ถูกใช้ประเมินรายบุคคล หรือหากใช้ ก็เปิดเผยแยกต่างหากและชัดเจน
      (หัวข้อ 1.1)

## รายการตรวจสอบการเปิดตัวแดชบอร์ด

- [ ] แดชบอร์ดมีกลุ่มผู้ชมและการตัดสินใจที่เฉพาะเจาะจงหนึ่งอย่างที่ระบุชื่อ
      (หัวข้อ 8.1)
- [ ] ตัวชี้วัดที่มีแรงจูงใจทุกตัวปรากฏในมุมมองเดียวกับ guardrail ของมัน
      (หัวข้อ 1.2, 8.1)
- [ ] แกนเริ่มที่ศูนย์ เว้นแต่มีข้อยกเว้นที่ระบุไว้และมองเห็นได้ชัดเจน
      (หัวข้อ 1.6)
- [ ] แสดงแนวโน้มตามเวลา ไม่ใช่ภาพนิ่งเพียงภาพเดียว (หัวข้อ 1.6)
- [ ] แดชบอร์ดมีเจ้าของที่ระบุชื่อและรอบการทบทวน (หัวข้อ 1.4)
- [ ] มีข้อความที่มองเห็นได้ประกาศว่าแดชบอร์ดนี้ไม่ได้มีไว้ทำอะไร หากเกี่ยวข้อง
      (หัวข้อ 1.1)
- [ ] แหล่งข้อมูลมีการตรวจสุขภาพเบื้องต้น เพื่อไม่ให้ไปป์ไลน์ที่เสียแสดงผลเงียบ ๆ
      ราวกับเป็นข้อมูลปัจจุบัน (หัวข้อ 1.5)

## รายการตรวจสอบการเริ่มใช้โครงการตัวชี้วัด

- [ ] สื่อสารจุดประสงค์และสิ่งที่ไม่ใช่เป้าหมายอย่างชัดแจ้งก่อนเริ่ม ไม่ใช่ตามหลังเมื่อมีปัญหา
      (หัวข้อ 8.3)
- [ ] ผู้ที่ถูกวัดมีส่วนร่วมในการเลือกตัวชี้วัด
      (หัวข้อ 8.3)
- [ ] โครงการเริ่มในโหมดเชิงวินิจฉัยอย่างเดียว พร้อมช่วงพิสูจน์ขั้นต่ำที่ผูกมัดไว้
      (หัวข้อ 8.3)
- [ ] มีโปรโตคอลตอบสนองที่รวดเร็วและมองเห็นได้ สำหรับเหตุการณ์การใช้ในทางที่ผิดในอนาคต
      (หัวข้อ 8.3)
- [ ] เลือกทีมนำร่องที่อาสาเข้าร่วมจริง ไม่ใช่ทีมที่ถูกสั่ง
      (หัวข้อ 8.5)
- [ ] การกำกับดูแลพื้นฐาน (กฎบัตร ความเป็นเจ้าของ นโยบายเชิงวินิจฉัย) พร้อม
      ก่อนเริ่มติดตั้งเครื่องมือวัด (หัวข้อ 1.4, 8.5)

## รายการตรวจสอบเหตุการณ์และ postmortem

- [ ] Postmortem สืบสวนที่ระบบ ไม่ใช่ตัวบุคคล
      (หัวข้อ 6.2)
- [ ] จัดระดับความรุนแรงตามเกณฑ์มาตรฐานที่บันทึกไว้
      (หัวข้อ 6.2)
- [ ] บันทึกเวลาตรวจพบ รับทราบ และแก้ไข แยกจากกัน
      (หัวข้อ 6.2)
- [ ] รายการดำเนินการเฉพาะเจาะจง มอบหมายผู้รับผิดชอบ และติดตามจนเสร็จ
      (หัวข้อ 6.2)
- [ ] แบ่งปัน postmortem โดยไม่ต้องกลัวผลกระทบต่อตัวบุคคล
      (หัวข้อ 6.2, 8.3)

## รายการตรวจสอบการตรวจสอบตัวชี้วัดในยุค AI

- [ ] ตัวชี้วัดบนแดชบอร์ดแต่ละตัวถูกทดสอบด้วยคำถามว่า "ทีมที่ใช้
      AI ช่วยอย่างหนักแต่ไม่ได้สร้างคุณค่าจริงเพิ่มขึ้น จะได้ค่าที่ดีขึ้น
      ตรงนี้หรือไม่" (หัวข้อ 7.1)
- [ ] ทบทวน change failure rate และ defect rate ควบคู่กับการเพิ่มขึ้น
      ของความถี่ในการ deploy หรือปริมาณคอมมิตที่ใช้ AI ช่วย (หัวข้อ 7.1)
- [ ] เฝ้าติดตามกำลังและความลึกของการรีวิว เมื่อปริมาณโค้ดที่ AI สร้างเปลี่ยนไป
      (หัวข้อ 7.1)
- [ ] ติดแท็ก escaped defect ตามระดับการใช้ AI ช่วย เพื่อทดสอบ ไม่ใช่สันนิษฐาน
      ว่าความสัมพันธ์ของ defect rate ในอดีตยังคงอยู่หรือไม่
      (หัวข้อ 7.1, 7.3)
- [ ] มีวิธีตรวจจับที่ทนต่อข้อบกพร่องแบบ "ดูถูกต้อง" (mutation
      testing, property-based testing) สำหรับเส้นทางโค้ดที่พึ่ง AI มาก
      (หัวข้อ 7.3)
- [ ] กฎบัตรตัวชี้วัดถูกทบทวนและปรับปรุงอย่างชัดแจ้งเพื่อรองรับการเปลี่ยนแปลงนี้
      ไม่ได้ปล่อยให้ลอยไปโดยไม่ตรวจสอบ (หัวข้อ 1.4, 7.1)

## รายการตรวจสอบการตรวจสอบโครงการตัวชี้วัด (ประจำปี)

- [ ] ตัวชี้วัดทุกตัวยังคงมีเจ้าของที่ระบุชื่อ (หัวข้อ 1.4)
- [ ] ตัวชี้วัดอย่างน้อยหนึ่งตัวถูกยกเลิกในรอบที่ผ่านมา หากมันไม่คุ้มค่าที่จะเก็บไว้อีกต่อไป
      (หัวข้อ 1.1)
- [ ] ประเมินวุฒิภาวะห้ามิติอย่างซื่อตรง
      ให้คะแนนตามค่าต่ำสุด ไม่ใช่ค่าเฉลี่ย (หัวข้อ 8.4)
- [ ] ไม่มีตัวชี้วัดใดเลื่อนจากการใช้เชิงวินิจฉัยไปเป็นเชิงประเมินผล
      โดยไม่มีการตัดสินใจที่ชัดแจ้งและเปิดเผย (หัวข้อ 1.1)
- [ ] สุ่มตรวจคำจำกัดความเทียบกับการติดตั้งเครื่องมือวัดจริง เพื่อหาการคลาดเคลื่อน
      (หัวข้อ 1.2, 2.4, 5.1, 6.2, 6.4)
- [ ] คำนวณและทบทวนอัตราส่วน outcome ต่อ output บนแดชบอร์ดหลักแล้ว
      (หัวข้อ 7.4)
