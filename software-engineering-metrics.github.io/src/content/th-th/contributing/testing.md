# การทดสอบ: ชุดตรวจสอบความถูกต้อง

## วิธีรัน

```sh
just test
# or
python3 tests/validate.py
```

รันจากที่ไหนก็ได้ และต้องการเพียง Python 3 (ไม่มีแพ็กเกจภายนอก ไม่ใช้เครือข่าย)
มันพิมพ์หนึ่งบรรทัดต่อหนึ่งการตรวจ และออกด้วยรหัสไม่ใช่ศูนย์หากการตรวจใดไม่ผ่าน
จึงใช้ใน CI และเป็น pre-commit hook ได้

## สิ่งที่ตรวจ

- **จำนวนหัวข้อที่คาดไว้** (ค่าคงที่ที่ต้นสคริปต์)
- **เลขต่อเนื่อง** ภายในแต่ละส่วน เริ่มที่ N.0
- **H1 ตรงกับเลขทศนิยมของชื่อไฟล์** ในทุกหัวข้อ
- **ชื่อเรื่อง H1 ตรงกับ `spec/structure.md`** ตัวอักษรต่อตัวอักษร ไม่ใช่แค่เลขทศนิยมนำหน้า
- **ส่วนที่กำหนด** มีครบในทุกหัวข้อเนื้อหา (ส่วนที่ 1 ถึง 8
  หัวข้อ N.1 ขึ้นไป) **ตามลำดับของเทมเพลตเป๊ะ**
- **จำนวนคำขั้นต่ำ** สำหรับทุกหัวข้อเนื้อหา (1,500 คำ) พร้อมรายการยกเว้นในสคริปต์
  สำหรับข้อยกเว้นที่ตั้งใจ
- **ไม่มีเส้นประยาว** ในไฟล์ Markdown ใด ๆ
- **เส้นประสั้นเฉพาะระหว่างตัวเลข** ดังนั้น "2.1–2.8" ผ่าน และอย่างอื่นไม่ผ่าน
- **ไม่มีวลีต้องห้าม** ("not only", "but also", "load-bearing")
- **ลิงก์ `.md` ภายในทั้งหมดต้องมีปลายทางจริง**
- **การอ้างอิงข้ามในเนื้อความชี้ไปยังหัวข้อจริง**: การอ้างถึงเลขหัวข้อที่ไม่มีไฟล์ตรงกัน
  ในดิสก์จะไม่ผ่าน โดยใช้รูปแบบการอ้างอิงเดียวกับที่เว็บไซต์ที่เผยแพร่ใช้
  เพื่อลิงก์หัวข้ออัตโนมัติ
- **ลิงก์ Wikipedia มีรูปแบบถูกต้อง** (`https://en.wikipedia.org/wiki/...`)
- **`spec/structure.md` ตรงกับไฟล์ในดิสก์** ทั้งสองทิศทาง
- **README หน้าแรก และหน้าสารบัญ ลิงก์ถึงทุกหัวข้อ**

## เมื่อการตรวจไม่ผ่าน

บรรทัดที่ไม่ผ่านจะระบุไฟล์และปัญหา วิธีแก้ที่พบบ่อย:

- พบเส้นประยาว: เรียบเรียงประโยคใหม่เพื่อเอาเส้นประยาวออก อย่าเพียงลบทิ้ง
- ขาดส่วน: เพิ่มส่วน `##` ที่ขาดจากเทมเพลตหัวข้อ
- โครงสร้างไม่ตรง: คุณเพิ่มหรือเปลี่ยนชื่อหัวข้อโดยไม่อัปเดต
  `spec/structure.md` หรือกลับกัน ให้ปรับให้ตรงกัน
- ลิงก์เสีย: แก้พาธ หรืออัปเดตหลังการเปลี่ยนชื่อ
- เลขขาดช่วง: ให้เลขใหม่เพื่อให้ส่วนต่อเนื่องตั้งแต่ N.0

## นอกเหนือจากชุดตรวจสอบ

- `just spell` รัน [codespell](https://github.com/codespell-project/codespell)
  ทั่วทั้ง repository การตั้งค่า รวมถึงรายการละเว้นผลบวกลวง
  อยู่ในส่วน `[tool.codespell]` ของ `pyproject.toml`
- `just stats` พิมพ์รายงาน Markdown (จำนวนคำต่อหัวข้อ หัวข้อที่บาง
  ลิงก์ Wikipedia รายการอ้างอิง) จาก `tools/stats.py`

## การทำ Continuous integration

- `.github/workflows/test.yml` รันทุก pull request และทุกการ push ไปยัง
  branch ที่ไม่ใช่ main: ชุดตรวจสอบและ codespell repository นี้
  ไม่ build หรือ deploy เว็บไซต์ การเรนเดอร์เกิดขึ้นใน repository
  `software-engineering-metrics.github.io` ที่แยกออกมา
- `.github/workflows/links.yml` ตรวจลิงก์ภายนอกทุกสัปดาห์ด้วย
  [lychee](https://github.com/lycheeverse/lychee) (รูปแบบที่ละเว้นอยู่ใน
  `.lycheeignore`) และเก็บผลไว้ใน issue "Link checker report" เดียว
  ลิงก์ภายนอกอยู่นอกเส้นทางของ PR โดยตั้งใจ

## สิ่งที่การทดสอบไม่ครอบคลุม

ชุดตรวจสอบตรวจโครงสร้างและสไตล์ ไม่ใช่ความจริง มันบอกไม่ได้ว่าเอกสารอ้างอิงเป็นของจริงหรือไม่
หรือเนื้อความถูกต้องหรือไม่ ให้ตรวจการอ้างอิงและข้อเท็จจริงด้วยมือหรือด้วยการค้นคว้า
การมีอยู่ของลิงก์ Wikipedia (ต่างจากรูปแบบลิงก์) ก็ต้องตรวจผ่านเครือข่ายเช่นกัน
ซึ่งชุดตรวจสอบตั้งใจละไว้เพื่อให้รันแบบออฟไลน์ได้
