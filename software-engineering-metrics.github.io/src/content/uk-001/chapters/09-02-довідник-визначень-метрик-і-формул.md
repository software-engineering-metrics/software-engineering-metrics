# 9.2 Довідник визначень метрик і формул

Кожна формула книжки, зібрана в одному місці. Кожен запис називає тему з
повним обговоренням, включно з ризиком маніпулювання й запобіжником.
Користуйтеся цим як швидким довідником, а не заміною самої теми.

## Метрики потоку (частина 2)

| Метрика | Формула | Тема |
| --- | --- | --- |
| Швидкість потоку | Кількість завершених елементів потоку за одиницю часу | 2.3 |
| Розподіл потоку | (Завершені елементи одного типу елементів потоку) / (Усі завершені елементи) x 100% | 2.3 |
| Час потоку | Час від входу елемента потоку в потік створення цінності до його постачання | 2.4 |
| Навантаження потоку | Кількість елементів потоку, що наразі активні чи очікують у потоці створення цінності | 2.4 |
| Закон Літтла | Навантаження потоку (незавершена робота) = Інтенсивність надходження x Час потоку (час циклу) | 2.4, 2.7 |
| Ефективність потоку | Активний робочий час / Загальний плин часу x 100% | 2.5 |
| Час циклу | Сума тривалостей етапів: кодування + очікування рев'ю + рев'ю + тестування + розгортання | 2.6 |
| Завантаженість | Інтенсивність надходження / Інтенсивність обслуговування | 2.7 |
| Відсоток повного й точного (%C/A) | (Одиниці, придатні нижче за потоком без переробки) / (Усі одиниці) x 100% | 2.8 |
| Сукупний вихід придатних | %C/A етапу 1 x %C/A етапу 2 x ... x %C/A етапу N | 2.8 |
| Такт-тайм | Доступний робочий час / Попит клієнтів за цей період | 2.8 |
| Час до першого рев'ю | Час від відкриття pull request до першої змістовної відповіді рецензента | 2.9 |
| Частота розгортань | Кількість успішних розгортань у продакшен за одиницю часу | 2.10 |
| Час виконання змін | Час від першого коміту до успішного розгортання в продакшен (повідомляйте медіану та 90-й перцентиль) | 2.10 |
| Частка невдалих змін | (Розгортання, що спричинили збій) / (Усі розгортання) x 100% | 2.10 |
| Час відновлення після невдалого розгортання | Час від виявлення збою до справжнього відновлення сервісу | 2.10 |

## Досвід розробника (частина 3)

| Метрика | Формула | Тема |
| --- | --- | --- |
| Час зосередження | Кількість і тривалість безперервних блоків понад дві години на тиждень, за даними календаря | 3.6 |
| Частка відповідей | (Отримані відповіді на опитування) / (Надіслані запрошення до опитування) x 100% | 3.7 |

## Код і якість (частина 4)

| Метрика | Формула | Тема |
| --- | --- | --- |
| Цикломатична складність | Незалежні шляхи в потоці керування (ребра − вузли + 2, за McCabe) | 4.1 |
| Покриття тестами | (Рядки/гілки, виконані тестами) / (Усі рядки/гілки) x 100% | 4.2 |
| Частка вбитих мутантів | (Мутанти, вбиті набором тестів) / (Усі внесені мутанти) x 100% | 4.2 |
| Плинність коду | Додані + змінені + видалені рядки на файл за часовий проміжок | 4.3 |
| Оцінка гарячої точки | Плинність x Складність, ранжовано за файлами | 4.3 |
| Вартість утримання боргу | Оцінена постійна вартість невиправлення елемента (повільніша суміжна робота, підвищений ризик дефектів) | 4.5 |

## Продукт і бізнес (частина 5)

| Метрика | Формула | Тема |
| --- | --- | --- |
| Рівень дефектів, що прослизнули | (Зважені за серйозністю дефекти, що прослизнули) / (Одиниця постачання чи часу) | 5.1 |
| Початкове впровадження | (Користувачі, що спробували функцію принаймні раз) / (Цільова аудиторія) x 100% | 5.2 |
| Утримане впровадження | (Користувачі, що досі користуються функцією через N тижнів) / (Користувачі, що спершу її спробували) x 100% | 5.2 |
| Вартість одиниці | Загальна вартість (люди + інфраструктура + інструменти) / Змістовна одиниця (клієнт, транзакція) | 5.4 |
| ROI | (Загальна вигода − Сукупна вартість володіння) / Сукупна вартість володіння, подана як діапазон | 5.5 |

## Надійність, експлуатація та безпека (частина 6)

| Метрика | Формула | Тема |
| --- | --- | --- |
| Бюджет помилок | (1 − ціль SLO) x Часове вікно (наприклад, 0,1% від 30 днів ≈ 43 хвилини) | 6.1 |
| Швидкість вичерпання бюджету помилок | Спожитий бюджет помилок / Виділений бюджет помилок за певне вікно | 6.1 |
| MTTD | Час від початку інциденту до виявлення | 6.2 |
| MTTA | Час від сповіщення про інцидент до підтвердження | 6.2 |
| MTTR (інцидент) | Час від підтвердження до справжнього відновлення сервісу | 6.2 |
| Розподіл викликів чергування | Виклики, отримані на людину, за ковзним вікном (а не середнє по команді) | 6.3 |
| Час усунення вразливості | Час від виявлення до справжнього усунення, відстежуваний за серйозністю | 6.4 |

## Примітки щодо використання цих формул

- **Завжди поєднуйте формулу швидкості чи випуску з її запобіжником** (тема
  1.2): частку невдалих змін із частотою розгортань і часом виконання; рівень
  дефектів, що прослизнули, зі швидкістю постачання; швидкість вичерпання
  бюджету помилок з активністю розгортань.
- **Для часових формул використовуйте медіани й перцентилі, а не середні**
  (тема 1.6), якщо формула явно не вимагає середнього.
- **Кожна формула потребує задокументованої системи-джерела й способу збору**
  (тема 1.5) поряд зі своїм математичним визначенням; дві команди, що
  обчислюють ту саму формулу з різних джерел, не дадуть порівнянних чисел.
- **Зважування за серйозністю показано явно не в кожній формулі вище**, але воно
  застосовне всюди, де з'являється «зважені за серйозністю»; повну схему
  класифікації дивіться у відповідній темі.
