# Тестування: набір перевірок

## Запуск

```sh
just test
# or
python3 tests/validate.py
```

Він запускається звідусіль і потребує лише Python 3 (без сторонніх пакетів і
без мережі). Друкує по рядку на кожну перевірку й завершується з ненульовим
кодом, якщо якась перевірка не пройшла, тож годиться для CI і як pre-commit-хук.

## Що він перевіряє

- **Очікувану кількість тем** (константа на початку скрипта).
- **Безперервну нумерацію** в кожній частині, починаючи з N.0.
- **Збіг H1 з назвою файлу** за десятковим номером для кожної теми.
- **Збіг заголовків H1 із `spec/structure.md`** символ у символ, а не лише
  початковий десятковий номер.
- **Обов'язкові розділи** в кожній змістовній темі (частини 1–8, теми N.1 і
  далі) **точно в порядку шаблону**.
- **Мінімальну кількість слів** для кожної змістовної теми (1500), зі списком
  винятків у скрипті для навмисних відступів.
- **Відсутність довгих тире** в усіх файлах Markdown.
- **Короткі тире лише між цифрами**, тож «2.1–2.8» проходить, а решта ні.
- **Відсутність заборонених зворотів** («not only», «but also», «load-bearing»).
- **Усі внутрішні посилання `.md` ведуть куди слід.**
- **Перехресні посилання в прозі вказують на справжні теми**: посилання на номер
  теми без відповідного файлу не проходить, за тим самим шаблоном посилання, що
  його використовує автоматичне створення посилань на теми на опублікованому
  сайті.
- **Посилання на Wikipedia мають правильну форму** (`https://en.wikipedia.org/wiki/...`).
- **`spec/structure.md` збігається з файлами на диску** в обидва боки.
- **README, головна сторінка та сторінка змісту посилаються на кожну тему.**

## Коли перевірка не проходить

У рядку з помилкою названо файл і проблему. Типові виправлення:

- Знайдено довге тире: переформулюйте речення, щоб прибрати «—». Не просто
  видаляйте його.
- Бракує розділу: додайте відсутній розділ `##` із шаблону теми.
- Розбіжність зі структурою: ви додали чи перейменували тему без оновлення
  `spec/structure.md` або навпаки. Приведіть їх у відповідність.
- Зламане посилання: виправте шлях або оновіть його після перейменування.
- Прогалина в нумерації: перенумеруйте, щоб частина була безперервною з N.0.

## Крім набору перевірок

- `just spell` запускає [codespell](https://github.com/codespell-project/codespell)
  по репозиторію. Конфігурація, зокрема список ігнорованих хибних спрацювань,
  міститься в розділі `[tool.codespell]` файлу `pyproject.toml`.
- `just stats` друкує звіт у Markdown (кількість слів по темах, тонкі теми,
  посилання на Wikipedia, записи джерел) за допомогою `tools/stats.py`.

## Безперервна інтеграція

- `.github/workflows/test.yml` запускається для кожного pull request і для
  пушів у гілки, відмінні від main: набір перевірок і codespell. Цей
  репозиторій не збирає й не розгортає сайт; відображення відбувається в
  окремому репозиторії `software-engineering-metrics.github.io`.
- `.github/workflows/links.yml` щотижня перевіряє зовнішні посилання за
  допомогою [lychee](https://github.com/lycheeverse/lychee) (шаблони винятків у
  `.lycheeignore`) і веде результати в одному issue «Link checker report».
  Зовнішні посилання навмисно не стоять на шляху pull request.

## Чого тести не покривають

Набір перевіряє структуру й стиль, а не істину. Він не може сказати, чи
справжнє джерело і чи точна проза. Перевіряйте цитати й факти вручну або
дослідницьким проходом. Існування посилань на Wikipedia (на відміну від їхньої
форми) теж потребує мережевої перевірки, яку набір навмисно не виконує, щоб
працювати офлайн.
