# Приклад: специфікація дашборда метрик постачання

Розібрана специфікація дашборда за
[темою 8.1, Проєктування дашборда інженерних метрик](../chapters/08-01-проєктування-дашборда-інженерних-метрик.md).
Важлива форма: названа аудиторія, невелике число плиток, чесний стандарт
візуалізації та заявлена періодичність оновлення.

## Аудиторія

Інженерне керівництво та платформна команда, перегляд на двотижневому огляді
постачання. Не призначений для оцінювання окремих людей.

## Плитки (у порядку показу)

1. **Частота розгортань**, останні 4 тижні, за командами. Лінійний графік,
   тижневі інтервали, вісь починається з нуля.
2. **Час виконання змін**, медіана та 90-й перцентиль, останні 4 тижні.
   Стовпчикова діаграма з обома рядами, а не лише з медіаною.
3. **Частка невдалих змін**, останні 4 тижні, із посиланням на узгоджене
   командою визначення «невдачі».
4. **Час відновлення після невдалого розгортання**, медіана, останні 4 тижні.
5. **Залишок бюджету помилок**, поточний квартал, за сервісами, у відсотках.

## Правила візуалізації

- Кожен графік тренду показує щонайменше вісім точок даних, ніколи не один
  знімок.
- Осі починаються з нуля, якщо виняток не задокументований на плитці.
- Розгортання, інциденти та свята позначені на часовій осі, щоб читач відрізнив
  справжній зсув від шуму.
- Жодних подвійних осей, 3-D-ефектів чи вибірково дібраних діапазонів дат.

## Періодичність оновлення

Плитки з даними конвеєра (частота розгортань, час виконання) оновлюються щогодини.
Плитки з даними інцидентів (частка невдалих змін, час відновлення) оновлюються
після закриття постмортему. Дашборд показує власний час останнього оновлення.

## Що цей дашборд свідомо виключає

Кількість комітів окремих людей, кількість pull request окремих людей і рядки
коду. Це метрики активності з добре задокументованою історією маніпулювання та
вимірювання зусиль, а не результату (тема 3.4).
