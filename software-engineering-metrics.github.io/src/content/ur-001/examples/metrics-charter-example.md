# مثال: ادائیگیوں کے پلیٹ فارم کی ٹیم کے لیے میٹرکس کا چارٹر

میٹرکس کے چارٹر کی عملی مثال، وہ ایک صفحے کی دستاویز جو
[موضوع 1.4، میٹرکس کی گورننس اور ملکیت](../chapters/01-04-میٹرکس-کا-نظم-و-نسق-اور-ملکیت.md) میں بیان ہوئی۔ اصل بات شکل ہے: بیان کردہ مقصد،
صریح غیر مقاصد، نام زد مالک، اور جائزے کا وقفہ۔ اس سائز کا چارٹر پڑھے جانے کے لیے ہے، فائل میں دبانے کے لیے نہیں۔

- **ٹیم:** ادائیگیوں کا پلیٹ فارم
- **مالک:** پلیٹ فارم انجینئرنگ مینیجر
- **جائزہ:** ہر سہ ماہی، پلیٹ فارم ریویو میں

## مقصد

یہ چارٹر ان میٹرکس کو منظم کرتا ہے جو ادائیگیوں کے پلیٹ فارم کی ٹیم اپنی ترسیل اور قابلِ اعتماد ہونے کے بارے میں ٹریک کرتی ہے۔ یہ اس لیے موجود ہے کہ ٹیم کے اندر اور باہر ہر کوئی
دیکھ سکے کہ کیا ناپا جاتا ہے، کیوں، اور کس لیے استعمال نہیں ہوتا۔

## ہم کیا ٹریک کرتے ہیں

| میٹرک | سچائی کا ماخذ | مالک |
| --- | --- | --- |
| ڈیپلائمنٹ کی تعدد | CI/CD پائپ لائن | پلیٹ فارم لیڈ |
| تبدیلیوں کا لیڈ ٹائم | Git اور ڈیپلائمنٹ پائپ لائن | پلیٹ فارم لیڈ |
| تبدیلی کی ناکامی کی شرح | واقعات کا ٹریکر، ہر ڈیپلائمنٹ پر ٹیگ شدہ | آن کال لیڈ |
| ناکام ڈیپلائمنٹ سے بحالی کا وقت | واقعات کا ٹریکر | آن کال لیڈ |
| P99 API تاخیر (SLI) | آبزرویبلیٹی پلیٹ فارم | SRE لیڈ |
| ایرر بجٹ کا خرچ | آبزرویبلیٹی پلیٹ فارم | SRE لیڈ |

## غیر مقاصد

یہ میٹرکس کبھی، انفرادی طور پر یا مجموعی طور پر، انجینئروں کی درجہ بندی کرنے، کارکردگی کے جائزوں پر فیصلے کرنے، یا اس ٹیم کا کسی دوسری ٹیم کے روڈ میپ سے موازنہ کرنے کے لیے استعمال نہیں ہوتے
جب تک دائرہ کار، عملے کی تعداد، اور نظام کی پختگی کا موازنہ بھی نہ ہو۔ اوپر بیان کردہ مقصد سے باہر کسی بھی استعمال کے لیے انجینئرنگ ڈائریکٹر اور خود ٹیم کی منظوری درکار ہے۔

## حفاظتی حدیں

اوپر ہر وہ میٹرک جو ترغیب رکھتا ہے ایک حفاظتی حد کے ساتھ جوڑا گیا ہے۔ تبدیلیوں کے لیڈ ٹائم کو تبدیلی کی ناکامی کی شرح کے ساتھ دیکھا جاتا ہے تاکہ ٹیم زیادہ خطرناک تبدیلیاں
بھیج کر اپنی رفتار کا عدد بہتر نہ کر سکے۔ ڈیپلائمنٹ کی تعدد کو اسی وجہ سے ایرر بجٹ کے خرچ کے ساتھ دیکھا جاتا ہے۔

## جائزے کا وقفہ

ٹیم اس چارٹر کا ہر سہ ماہی جائزہ لیتی ہے۔ جس میٹرک نے لگاتار دو سہ ماہیوں میں کوئی فیصلہ نہیں بدلا وہ ریٹائرمنٹ کا امیدوار ہے۔
