# 5.0 第5部分导言：产品与业务指标

本书的前四部分衡量的是工程的内部世界：交付、开发者体验和代码质量。这一部分跨出这个边界，提出每一项工程指标最终都为之服务的问题，无论是直接服务、还是隔着几步之遥：这项工作是否真正帮助了业务，以及使用它所构建之物的人。第1.3章在本书早期确立了结果优先于产出作为一项指导原则；这一部分正是这项原则遇到最严峻考验的地方，因为产品和业务结果离任何单一工程师的直接控制最远，也最难被干净利落地归因回工程投入。

这种困难恰恰是这一部分之所以重要的原因。一个从未把自己的交付和质量指标与产品和业务结果连接起来的组织，冒着为错误的东西做出漂亮优化的风险：快速发布一项没有人使用的功能，测试覆盖率极佳，或者在一个核心价值主张已经悄悄不再让客户在意的系统上维持一尘不染的代码质量。这一部分的五章，逃逸缺陷、功能采用、客户与业务结果、单位经济学，以及投资回报，给了工程领导层一套用于建立这种联系的词汇，也给了业务领导层一种能用真正对他们而言重要的说法来评估工程投资的方式。

对大团队而言，这一部分往往是整套指标项目在高管利益相关方那里赢得或失去可信度的地方。批准数百万美元平台投资的企业领导层，以及批准公共技术预算的政府监督机构，都需要用业务或公民结果的说法来表述的答案，而不是部署频率或测试覆盖率，无论那些内部指标被管理得多好。这一部分正是本书其余部分那些经过精心护栏保护的指标，最终连接到那场面向外部、面向结果的对话的地方。

## 本部分各章

- **5.1 逃逸缺陷率与质量逃逸：** 最直接反映客户实际体验的质量指标，有别于第4部分的内部质量指标。
- **5.2 功能采用与使用指标：** 工程所构建的东西是否真正被使用，以及采用数据被误读的具体方式。
- **5.3 客户与业务结果指标：** 把工程工作与一项业务或一项公共使命真正在意的结果连接起来。
- **5.4 工程的成本与单位经济学：** 用一位财务利益相关方能够直接使用的说法来表达工程成本。
- **5.5 工程举措的投资回报：** 为一项重大工程投资建立一个站得住脚、诚实的投资回报论证，并在论证站不住脚时同样诚实。

## 这些章节如何相互关联

第5.1章从离本部分最近的地方开始，也就是客户直接体验到的质量，它是从第4部分内部质量指标过渡过来的自然桥梁。第5.2章在质量被纳入考量之后提出下一个问题：是否真的有人使用了被构建出来的东西。第5.3章把视角进一步扩展到一个组织所关心的完整范围的客户和业务结果，使用情况只是其中众多信号之一。第5.4章和第5.5章随后把整个部分转向财务：用与预算和投资决策直接相关的说法来表达工程成本和回报，回答这一部分开篇提出的问题：工程投入是否真正有所帮助。

这一部分的各章特别倚重第1.6章的统计素养，因为业务和产品结果常常充满噪声，受市场条件的干扰，也需要很长时间才能确认，这恰恰是第1.6章所警告的那些错误最容易产生一个自信却错误的结论的条件。把这一部分与第7部分一并阅读，那里向生成式人工智能的转变，提高了把结果测量做对的风险，具体原因正是这一部分各章自始至终所论证的：产出量本来就从来不是正确的优化对象。
