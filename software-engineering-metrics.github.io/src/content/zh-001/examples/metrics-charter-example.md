# 示例：支付平台团队的指标章程

一份具体的指标章程示例，即
[主题 1.4，指标的治理与所有权](../chapters/01-04-指标治理与所有权.md)中所描述的一页纸文件。关键在于形式：明确的目的、
明确的非目标、具名的所有者，以及评审节奏。这样篇幅的章程是用来读的，不是用来归档的。

- **团队：**支付平台
- **所有者：**平台工程经理
- **评审：**每季度，在平台评审会上

## 目的

本章程管理支付平台团队就自身交付和可靠性所跟踪的指标。它的存在，是为了让团队内外的所有人都能看到衡量的是什么、为什么衡量，以及它不用于什么。

## 我们跟踪什么

| 指标 | 事实来源 | 所有者 |
| --- | --- | --- |
| 部署频率 | CI/CD 流水线 | 平台负责人 |
| 变更前置时间 | Git 加部署流水线 | 平台负责人 |
| 变更失败率 | 事件跟踪器，按部署打标签 | 值班负责人 |
| 从失败部署中恢复的时间 | 事件跟踪器 | 值班负责人 |
| P99 API 延迟（SLI） | 可观测性平台 | SRE 负责人 |
| 错误预算消耗 | 可观测性平台 | SRE 负责人 |

## 非目标

这些指标无论单独还是合并，都绝不用于给工程师排名、评判绩效考核，或在没有同时比较范围、人员编制和系统成熟度的情况下，拿这个团队与另一个团队的路线图作比较。
任何超出上述目的的用途，都需要工程总监和团队本身的批准。

## 护栏

上面每一项带有激励的指标，都与一道护栏配对。变更前置时间与变更失败率一起受到监控，这样团队就无法靠交付风险更高的变更来改善速度数字。
部署频率出于同样的原因，与错误预算消耗一起受到监控。

## 评审节奏

团队每季度评审一次本章程。连续两个季度没有改变任何决策的指标，是退休的候选对象。
