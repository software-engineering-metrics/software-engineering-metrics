# 3.1 SPACE框架

## 概述与动机

**[SPACE框架](https://queue.acm.org/detail.cfm?id=3454124)**由研究者Nicole Forsgren、Margaret-Anne Storey、Chandra Maddila、Thomas Zimmermann、Brian Houck和Jenna Butler于2021年发表，其构建是为了回答一个具体的问题：单一数字的[开发者生产力](https://en.wikipedia.org/wiki/Productivity)指标，代码行数、提交次数、故事点，极易被操纵，并常常带来误导。SPACE提出转而跨五个维度进行衡量：**满意度与幸福感**、**绩效**、**活动**、**沟通与协作**，以及**效率与心流**。没有任何一个字母是打算单独成立的；这个框架真正的贡献，在于把全部五个维度一并纳入视野的纪律，这样一个团队就无法靠悄悄损害另一个轴，而在某一个轴上显得富有生产力。

这一点之所以重要，是因为开发者生产力不是单一的东西。一个团队可以非常活跃（很多提交、很多拉取请求），同时表现不佳（工作没有推动真正重要的结果）。一个团队可以在短期内表现良好，同时满意度骤降，这是数月后才会显现的人员流失和质量崩溃的一个先行指标。SPACE的洞见，直接建立在本书主题 1.2 与主题 1.3 之上，是这些维度中的任何一个，一旦被当作独立的目标去追逐，都会以损害其他维度为代价被操纵，而这个框架的存在，正是为了在这种权衡造成真正损害之前让它显现出来。

对大团队而言，SPACE为领导层提供了一套共享的词汇，用于一场原本会默认沦为"哪个维度最容易衡量就谈哪个"的对话，而那几乎总是活动维度。跨越许多团队比较生产力的企业组织，需要一个能抵御"数提交次数"这种拉力的框架；在一个竞争激烈的劳动力市场中面临招聘与留任压力的政府组织，需要像重视交付数据一样认真地重视满意度与幸福感数据，因为因职业倦怠而失去一名经验丰富的工程师，其代价远远超过任何单个迭代所曾节省下来的产出。

## 核心原则

- **没有任何单一的SPACE维度单独是可信的。** 这个框架的价值恰恰来自同时衡量多个维度。
- **至少从三个维度各取至少一项指标，并混合主观与客观数据来源，是获得均衡图景的最低要求。** 一套完全取自单一维度或单一数据类型的指标集，并不算真正在使用SPACE。
- **活动是最容易被滥用为独立代理指标的维度。** 它最容易衡量，单独来看也最不能代表真实价值。
- **团队层面与个人层面的测量需要不同的处理方式。** SPACE的设计主要是为了团队和系统层面的洞察，而不是为了个人记分卡。
- **五个维度会相互作用。** 一项改善某个维度的变化可能会损害另一个维度，而这个框架的存在正是为了捕捉这种权衡。

## 建议

### 在信任你的指标集之前，先从至少三个维度构建它

不要挑一个自己偏爱的单一维度（通常是活动或绩效）来采用SPACE，然后就当作完成了。在就团队生产力提出任何结论之前，有意识地从五个维度中的至少三个各选取至少一项指标，把客观埋点（主题 1.5）与主观调查数据（主题 3.7）混合起来。正是这个最低构成，防止了SPACE退化回它本应解决的那种单一代理指标问题。

### 把活动指标当作背景信息，绝不当作头条

提交次数、代码行数和拉取请求数量都是合法的SPACE活动维度数据，但它们绝不应该是关于一个团队生产力所呈现的主要或唯一指标。用活动数据为其他维度提供背景，例如留意到活动量下降恰逢满意度上升，是因为团队终于有空间偿还技术债务，而不是把它当作一个独立的裁决。主题 3.4 深入探讨了这个维度的具体风险。

### 在团队与系统层面应用SPACE，而不是在个人层面

SPACE最初的研究及其后续在业界的采用，都把这个框架当作理解团队和组织生产力的一面透镜，而不是个人绩效记分卡。把SPACE的各个维度用来给个人排名，尤其是活动维度，恰恰重现了主题 1.2 所警告的那种操纵风险，也误用了一个从未针对那种用途被验证过的框架。

### 留意维度之间的权衡取舍，而不只是单一维度内部的变动

这个框架真正的诊断力量，来自观察各维度相对彼此如何变动。绩效指标上升的同时满意度下降，是一个值得立即调查的警示信号，可能表明节奏不可持续。活动指标上升的同时绩效持平或下降，则暗示的是忙碌而非真正的进展。以固定节奏一并审阅全部五个维度，专门用来捕捉这些跨维度的模式，而不只是孤立地检查每个数字。

### 在各维度之间恰当地混合审阅节奏

一些SPACE维度变化缓慢，最适合定期衡量（满意度，通常按季度调查周期）；另一些变化很快，受益于更频繁的自动化跟踪（活动，以及效率与心流，两者大多都能从现有系统中埋点获得）。让你的测量节奏匹配每个维度自身的变化速度，而不是把每一项指标都硬塞进同一个报告日程。

## 权衡取舍：利与弊

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| 单一维度的指标集（通常是活动） | 简单、廉价、常见 | 容易被操纵，遗漏了不可持续做法所带来的人力成本 |
| 完整采用五个维度的SPACE | 均衡，抵御单轴操纵，能捕捉权衡取舍 | 需要更多的埋点和调查投入 |
| 团队层面应用SPACE | 符合这个框架经过验证的用法，保护个人不被误用指标 | 无法回答领导层有时想问的个人层面问题 |
| 个人层面应用SPACE | 对一些管理者而言感觉更直接可操作 | 误用了这个框架；带来强烈的操纵与士气风险 |

核心张力在于**测量的完整性与成本、复杂性**之间。一套完整、均衡的SPACE实施，比一份简单的活动仪表盘需要更多的埋点、更多的调查设计投入，以及更多把全部五个维度一并审阅的纪律。解决这种张力的办法，是从一套真正精简但均衡的集合开始，至少从三个维度各取至少一项指标，而不是要么完全跳过这个框架的纪律，要么在第一天就试图对全部五个维度做一次令人吃不消的全面埋点。

## 与团队讨论的问题

1. **我们当前的生产力指标集是取自至少三个SPACE维度，还是完全由活动数据主导？** 明确地把你的仪表盘对照这五个维度逐一审计；大多数组织，如果诚实评估的话，都比自己意识到的更偏重活动数据。

2. **我们是否曾见过某个SPACE维度改善、而另一个维度却在悄悄恶化，当时我们注意到了吗？** 这种跨维度的权衡，正是这个框架设计用来捕捉的东西。回顾过去一年中交付指标有所改善的一段时期，问问同一时期的满意度或幸福感数据显示了什么。

3. **SPACE数据是否曾经，哪怕只是非正式地，被用来评估或比较个人而不是团队？** 这误用了这个框架，并招致操纵。诚实地面对这些指标在实践中实际上是如何被讨论的，而不只是政策上声称它们应该如何被使用。

4. **如果一个团队以不可持续的节奏为代价改善了它的绩效指标，我们会如何察觉？** 如果没有把满意度与幸福感数据与绩效数据一并审阅，这种权衡在数月后以人员流失或质量崩溃的形式浮现之前，是不可见的。

5. **我们对这五个维度各自的测量节奏是什么，它是否匹配每个维度实际的变化速度？** 一份季度性的满意度调查配上实时的活动数据，是一种合理的节奏错配；不假思索地对全部五个维度套用同一节奏，则不是。

6. **如果一位新的工程经理明天入职，只看我们的仪表盘，他们看到的会是团队生产力的均衡图景，还是一幅偏斜的图景？** 这是对你的指标集是否真正达成了SPACE所要求的均衡，还是只是在实践中依然由活动数据主导、只是姿态上比划了一下这个框架的一次实际检验。

## 行业视角

**初创公司。** 对一小撮每天交流、能够直接感知满意度和协作健康状况的工程师来说，完整实施五个维度通常是过度的。值得及早养成的一个习惯，是当团队开始成长到非正式的相互了解不再能覆盖一切的规模时，抵御只用活动指标的拉力。

**小型企业。** 在没有专门的人员分析职能的情况下，保持简单：把你已有的任何交付数据（主题 2.10）与一次简短、非正式、定期的满意度沟通配对，哪怕只是一个简单的单一问题脉冲调查。这种最低限度的配对，已经比一份只有活动数据的仪表盘更好地捕捉了这个框架的核心纪律。

**企业。** 这正是完整框架发挥其复杂性价值的地方。在各团队之间标准化一套均衡的SPACE指标集，这样领导层就能公平地比较生产力，而不是默认看哪个团队的提交图看起来最令人印象深刻，并投资于主题 3.7 所述的调查基础设施，让满意度和协作数据像客观埋点数据一样可靠。

**政府。** 在公共部门薪酬往往无法与私营部门的报价竞争的地方，招聘与留任压力使满意度与幸福感数据成为一项真正具有战略意义的关切，而不是一个软性的附加项。在人力规划和预算论证中，像对待交付指标一样认真地对待SPACE，因为因职业倦怠而失去一名经验丰富的工程师，其代价是以数月计的机构知识，而一名替代者无法立即补上这些知识。

## 案例

**企业。** 一家软件公司的工程领导层多年来一直把提交次数和已完成的故事点作为其主要的生产力信号。在采用一套更完整的SPACE指标集，包括季度满意度调查和协作网络分析（主题 3.5）之后，领导层发现，活动数字最高的团队，其满意度分数也最低，随后一年的自愿离职率也最高。单独的活动数字一直在积极地误导人；更完整的图景促成了对该团队并发工作量的刻意削减（主题 2.5 的在制品原则应用于人的层面），随后满意度以及最终可持续的绩效都出现了可衡量的恢复。

**政府。** 一家国家数字服务机构，在与它无法匹敌的私营部门薪酬竞争工程人才时，专门采用了一套均衡的SPACE指标集，用以为非货币性的留任投资，更好的工具、受保护的专注时间、更少的流程摩擦，提出论证。满意度调查数据与效率和心流指标（主题 3.6）结合显示，打断频率，而不是薪酬，才是离职访谈数据中离职意愿最强的预测因子。该机构随后对受保护专注时间政策的投资，直接由这份SPACE数据论证支持，在接下来的十八个月里与留任率的可衡量改善相关联。

## 商业理由：动机、投资回报与总拥有成本

完整采用SPACE的回报，是避免了人员流失，避免了由职业倦怠驱动的质量崩溃，两者都远比这个框架的埋点成本昂贵得多。一套只有活动数据的指标集可以在一两年内看起来非常出色，直到人力成本一次性追赶上来，届时替换流失专业知识和重建团队健康的成本，会让这套狭窄指标集曾经呈现出的任何生产力收益相形见绌。

总拥有成本包括调查基础设施（主题 3.7），以及一并审阅全部五个维度、而不是默认只看最容易衡量的那个维度的纪律。这份成本确实值得付出：上面的企业案例展示了一种真实的、可被发现的模式，高活动量掩盖了高人员流失风险，而一套更狭窄的指标集本不会在损害已经造成之前揭示出来。

## 反模式与陷阱

- **只在名义上采用SPACE，实践中依然由活动数据主导：** 最常见的失败模式，它违背了这个框架的全部初衷。
- **把SPACE的各维度应用到个人记分卡上：** 误用了一个经过验证适用于团队与系统层面洞察的框架。
- **孤立地审阅各个维度，而不留意跨维度的权衡取舍：** 错过了SPACE专门设计用来捕捉的模式。
- **把每个维度都硬塞进同一个测量节奏：** 在变化缓慢的维度上浪费精力，同时对变化迅速的维度测量不足。
- **把单一一次满意度调查分数当作已经足够，而不辅以客观数据：** 失去了这个框架所要求的主观与客观来源之间的平衡。
- **因为另一个维度看起来不错，就忽视某一维度正在恶化的趋势：** 正是这个框架的跨维度纪律所要防止的失败。

## 成熟度模型

- **第一级，启动：** 生产力仅通过活动指标衡量，不收集满意度、协作或效率数据。
- **第二级，发展：** 一些额外的维度被非正式地衡量，但没有一致的跨维度审阅，也没有最低构成标准。
- **第三级，标准化：** 一套取自至少三个SPACE维度的均衡指标集，在全组织范围内一致地应用于团队层面。
- **第四级，管理：** 全部五个维度按固定节奏一并审阅，跨维度的权衡取舍被主动调查，这个框架为真实的人员配置和流程决策提供依据。
- **第五级，协奏：** SPACE数据直接塑造人力规划和留任投资，组织能够指出具体的干预措施，这些措施由跨维度的模式提供依据，并可衡量地同时改善了交付与开发者幸福感。

## 讨论思路

1. 在我们当前的指标集中，哪个SPACE维度最被低估、衡量最不足？
2. 我们是否曾见过某个团队的活动量上升，而满意度却在悄悄下降？
3. 我们今天要如何才能察觉一个团队正在用长期可持续性换取短期产出？
4. 目前是否有任何与SPACE相关的数据被用来评估个人而不是团队？
5. 对我们而言，一份真正均衡的生产力仪表盘，具体来说会是什么样子？

## 要点回顾

- SPACE涵盖五个维度，**满意度与幸福感、绩效、活动、沟通与协作，以及效率与心流**，没有任何一个单独是可信的。
- 从**至少三个维度**构建你的指标集，混合客观与主观数据来源。
- 把**活动指标当作背景信息**，绝不当作头条生产力信号（主题 3.4）。
- 在**团队与系统层面**应用SPACE，而不是把它当作个人记分卡。
- 把各维度一并审阅，留意**跨维度的权衡取舍**，而不只是任何单一维度内部的变动。
